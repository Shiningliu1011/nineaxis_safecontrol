# 笔记本与台式机协作

`lsn` 使用实验室笔记本电脑和课题室工位台式机，通过同一个 GitHub 仓库交替开发。
仓库地址为 `https://github.com/Shiningliu1011/nineaxis_safecontrol.git`，
当前工作分支为 `main`。
后续更换工作分支时，在接手记录中保存分支名。

## 开始工作

阅读当前设备适用的工作约定，检查本地改动、分支及远程地址，
随后获取远程状态：

```bash
git status --short --branch
git remote -v
git fetch origin
```

工作区没有待保存改动且处于当前工作分支时，执行：

```bash
git merge --ff-only origin/main
```

已有本地改动时保留内容，检查是否属于上次未推送的工作。
两边都有新提交时检查双方差异，使用普通合并解决冲突并验证受影响内容。
保留共同历史，不强制推送。

读取当前任务的 `prd.md`、`design.md`、`implement.md` 和接手记录。
主线接手入口为[完整项目地图](planning/nineaxis-full-project/README.md)与
[任务阻塞关系](planning/nineaxis-full-project/dependencies.md)。
新会话依据现有任务重新选择当前任务，不复制其他会话的运行状态。

## 结束工作或切换设备

1. 保存本次相关代码、配置、测试和文档，完成受影响验证。
2. 更新当前任务的实施记录和接手记录：已完成内容、实际验证、
   未完成事项、下一步入口、运行所用设备和本地数据位置。
3. 检查文件范围，按用户的同步授权提交并推送本次相关改动。
   提交格式为 `<type>(scope): <中文动词短语>`。
4. 核对远程分支已包含该提交，再到另一台设备继续工作。

当前双设备协作请求授权切换设备时同步本次项目工作。
用户后续要求仅检查、暂不提交或暂不推送时，以当次要求为准。
同一项工作完成同步后，再在另一台设备继续修改。

GitHub 上的代码、文档和任务记录用于跨设备接手；Codex 会话聊天记录
保存在各自使用的会话环境，关键决定需要写入项目接手记录。

## 数据与环境

GitHub 同步源码、配置、测试、规格、文档、Trellis 任务以及体积适当的结果摘要。
`output/`、`.scratch/`、构建环境和大型原始记录按 `.gitignore` 保存在本地。
首次迁移使用[完整资料包](project_migration.md)。

后续生成实验或标定数据时，在接手记录中注明：

- 数据生成设备与仓库相对目录。
- 运行身份、代码提交、场景和配置来源。
- 文件数量、容量和校验清单位置或 SHA-256。
- 验证结论与仍需原始记录才能进行的工作。

另一台设备需要这些原始记录时，传输相应资料包并核对校验值。
源机器的原始记录继续保留。报告读取使用项目的资源重定位接口，
保留原始来源身份和记录中的路径。

每台设备分别安装环境、构建项目并验证依赖，记录自身 CPU、GPU、
系统、Python、ROS 及磁盘容量。控制周期与耗时由当前运行设备实际测量。
正式实验清单和结果保存设备身份，按照规格维持方法之间的可比性。
