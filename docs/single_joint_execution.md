## 程序入口

[single_joint_execution.py](../src/robot_safecontrol_moveit/single_joint_execution.py) 提供 `run_single_joint(vendor, control, joint, delta_deg, limits, log_path, *, target_deg=None)`。每次调用只操作 J2–J9 中的一个关节；同一进程中其他执行请求会被拒绝。模块导入不打开设备、不发送命令。

`control` 使用 [DrEmpowerJointControl](../src/robot_safecontrol_moveit/drempower_joint_control.py)，从方向配置转换模型角度和电机角度。`delta_deg` 为相对当前位置的模型角度增量。使用绝对模型目标时传入 `delta_deg=None, target_deg=目标角度`。相对增量和绝对目标必须选择一项。`limits` 使用 `ExecutionLimits`；`ExecutionLimits.from_urdf(path, joint)` 通过 XML 库读取旋转关节限位。默认 `max_step_deg=None`，当前位置与目标位置均须处于 URDF 限位内；调用方可以通过 `max_step_deg` 设置本次操作的增量范围。

URDF 限位使用模型零点。软件零位偏移已根据用户确认的 URDF 零位姿态和静止读数中位数保存，来源为 `.scratch/motor_tools/diagnostic_final_preflight.json`。很小的非零读数保留原始精度，不代表测量准确度达到对应小数位数。J1 使用本页的独立直线轴接口，旋转关节终端入口支持 J2–J9。

终端入口为 [motor_cli.py](../src/robot_safecontrol_moveit/motor_cli.py)。[DrEmpowerSerial](../src/robot_safecontrol_moveit/drempower_serial.py) 使用 pyserial 独占串口连接，以 Construct 解析厂家标准模式串口帧，已有 `drempower_can` 负责 CAN 数据解码。启动时读取自动反馈配置，按设备设置接收命令回复，不自动使能、清错或修改设备参数。J4、J5、J6 自动反馈为 1，其他关节为 0。

本机 `.scratch/motor_connection_20261004/vendor/DrEmpower_can.py` 读取专用副本保留限制。新增依赖声明在 `setup.py` 的 `hardware` extra；本机串口依赖安装在 `.scratch/motor_tools/deps/`。

## 终端使用

参数预览不打开设备：

```bash
cd /home/lsn/robot/robot_safecontrol
PYTHONPATH=src:.scratch/motor_tools/deps python3 -m robot_safecontrol_moveit.motor_cli \
  --root "$PWD" \
  --port /dev/serial/by-id/usb-Dr-Tech_DR-USB_CAN_87949380174B-if00 \
  --output .scratch/motor_tools/J2_next.jsonl \
  move --joint J2 --delta-deg 10
```

`move` 增加 `--execute` 才发送运动命令；停止锁定存在时拒绝执行。上例每次实际执行都会从当前位置增加 10°。复验已有目标时，使用日志中的模型绝对目标，例如将最后一行替换为 `move --joint J8 --target-deg 5.072510242462158 --execute`。该数值属于对应测试姿态，使用前仍检查实际当前位置、目标和关节限位。输出文件必须尚不存在。

将最后一行替换为 `diagnose --joints J2 J3 J4 J5 J6 J7 J8 J9 --duration 5` 可进行只读诊断；电机需要供电。该入口只查询状态和属性，不发送位置命令。
诊断报告记录节点身份、轴状态、轴/CAN/motor/encoder/controller 故障码、母线电压、自动回复设置，以及实际位置和速度。新增的故障与电压字段尚待本次重新上电后采集；断电前日志无法补充这些读数。

`--speed-rpm` 允许 0.03–0.41 rpm，`--accel-rpm-s` 允许 0.01–0.1 rpm/s，两者均须为 0.01 的整数倍。协议速度分辨率为 0.01 rpm（0.06°/s），使用 `--speed-rpm 0.41` 可发送 2.46°/s；2.5°/s 无法被该速度字段精确表示。执行参数和串口发送共用 [motor_motion_limits.py](../src/robot_safecontrol_moveit/motor_motion_limits.py) 的参数校验，参数精度在打开串口前检查，参数预览、发送编码和观察时限使用相同数值。运动观察时限按实际运动角度除以指令速度、加上梯形加减速时间及 2 秒余量计算，至少为 20 秒。默认参数下，10° 运动的时限约为 36.33 秒；`move --joint J4 --delta-deg 10 --speed-rpm 0.03 --accel-rpm-s 0.02` 的时限约为 59.06 秒。相对运动预览可直接计算时限；绝对目标预览的 `motion_timeout_basis=feedback_distance` 表示需要取得实际位置后计算，预览中的 `motion_timeout_s` 为下限，发送记录保存实际采用的时限。

反馈速度保护上限为 2.5°/s（`max_feedback_rpm=2.5/6`）。默认指令速度仍为 0.3°/s；速度保护同时检查时间平均速度和位置变化速度。该参数配置已通过离线检查，J2 本次实机执行结果见本页现场状态。

## 检查与执行顺序

1. 检查 J2–J9 身份、有限非零增量或有效绝对目标，独占本进程的执行入口，以独立 JSONL 文件记录本次操作。
2. 检查节点处于闭环状态；获取并校验节点 ID、帧类型、故障标志、位置和速度。拒绝串口中的未请求数据。
3. 检查当前位置静止、当前及目标角度位于关节限位内。
4. 根据实际角度增量计算运动时限，将方向与零点换算后的单节点绝对目标交给 `set_angle(mode=1)`；发送前再次检查反馈时效。默认速度为 0.05 rpm（0.3°/s），加速度为 0.05 rpm/s（0.3°/s²）。
5. 每轮间隔 0.02 秒检查闭环状态和位置反馈。任一请求超时、反馈间隔超过 0.2 秒、位置突变、速度超过 2.5°/s、超出请求区间或超过按行程计算的运动时限仍未到位均终止执行。该间隔为主机轮询目标，不提供实时调度保证。
6. 位置进入 0.1° 容差且 `traj_done` 为真后，进入独立的静止观察阶段，时限由减速度及反馈观察参数确定，默认约 10.23 秒；所有保护继续生效，离开目标容差立即终止。位置误差不超过 0.1°、速度不超过 0.02 rpm 且 `traj_done` 连续满足至少 0.5 秒，才记录 `completed`。正常完成后电机继续保持已有位置目标。

静止实测中，快速反馈与独立速度属性均有瞬时波动，八个关节的位置变化范围小于 0.007°。程序保留原始速度，同时使用 1 秒速度时间平均值和最近 0.2 秒的位置变化速度，二者都必须满足速度阈值。两帧位置变化另有独立限制，位置测量裕量最多 0.01°。启动时先采集完整速度窗口再判断静止。

相邻位置变化检查使用 `max_feedback_rpm * 6 * (current.received_s - previous.request_s) + position_noise_deg`。主机请求、接收与设备采样时间分别保存其含义；日志标明设备采样时间未知。反馈过期、请求重复、轮询中断、位置变化超过上述范围及速度窗口超限继续拒绝。该主机一致性检查不提供设备采样年龄或瞬时物理速度证明。

超速中止后，保持请求独立验证位置身份、有限数值、故障、时间、范围及连续性；运动速度超限本身允许提出可信的当前位置保持请求。位置突变等不可信反馈保持拒绝。`hold_requested`、`hold_command_call_returned`、`hold_observed` 分别表示提出请求、调用返回与持续观察符合要求。保持观察超时保存最后未满足的条件、最长连续满足时间及原静止阈值，继续要求现场急停。

所有时间判断使用主机 `monotonic`。厂家反馈没有设备采样时间戳；请求时间只用于保守限制主机事务与轮询间隔，不证明设备内部数据新鲜度。错误帧、迟到或不完整回复会使当前读取会话拒绝继续使用，不能通过重复查询自动恢复。

## 异常停止

- 程序不会重发运动目标、自动恢复执行或继续下一个关节。
- 运动超时、超出请求区间或事务外 Ctrl+C 时，只有重新取得闭环且有效的当前位置，才尝试发送该位置作为保持目标。
- 保持请求之后，每轮独立查询闭环状态，再检查位置、速度与 `traj_done`；闭环状态和持续静止条件均满足时才记录 `hold_observed`。闭环退出或状态查询失败立即记录 `external_stop_required` 并提示现场急停。
- 保持观察时长为最大监控速度除以减速度，加上速度窗口、持续静止时间及事务余量，当前默认约 10.23 秒。等待超时记录 `external_stop_required`，不报告物理停车成功。
- 通信异常、驱动故障、反馈无法信任、保持失败等情况记录 `external_stop_required`，并打印“无法确认电机已经停止，请立即操作现场急停”。
- 未尝试发送运动命令时记录 `no_motion_command_attempted`。发送函数返回只说明厂家调用返回，不能替代到位或停车观察。

本程序没有独立硬件 watchdog，不能在进程被强制终止、主机断电或通信断开后继续运行。主机停止发送数据不能保证电机停止运动。急停会切断电机供电，机械保持条件必须独立验证。程序不自动调用会卸载电机的 `estop()`。
