# 跟踪平顺性与图片

控制周期决定位置命令多久更新一次。`dt` 决定 QP 速度转换为目标位置时采用的
积分步长；`dt_path` 决定参考路径每次推进的时间。执行器的仿真步长由
`config/oscbf_plant.yaml` 的 `publish_frequency_hz` 决定。

`SCurveDriverSimulator` 使用 Ruckig 生成连续运动，持续遵守配置中的速度、
加速度及 jerk 限制。每次位置目标更新保留当前速度与加速度；
`minimum_duration_s=0.08` 给每次运动规划规定 80 ms 的最短持续时间。
这项时间参数用于减小连续位置目标带来的重复加减速，与控制周期分别设置。
[Ruckig 官方说明](https://raw.githubusercontent.com/pantor/ruckig/v0.12.2/README.md)
介绍了当前运动状态、目标状态、最短持续时间及连续信号跟随的时间延迟。

## 控制与记录

当前组合为 20 ms 控制周期、10 ms QP 积分步长、20 ms 路径推进步长、
2 ms 执行器步长和 80 ms 最短运动规划时间。位置增益为 240，方向增益为
40，DLS 阻尼为 0.05。控制周期试验记录及各次参数保存在
`output/oscillation_fix/sweep_metrics.json`。

工具 X 轴跟随当前末端在路径上的投影点法向。参考方向随路径投影变化产生的
转动直接计入任务 Jacobian。位置参考提前量保持 2 mm，方向参考由当前位置的
投影确定。

终点附近继续满足位置、方向、QP 和执行器限制。在反馈尚未经过终点截面时，
加入 0.1 mm/s 的切向驱动分量。位置及方向在原有容差内保持 0.5 s，且反馈
投影已经到达路径终点后进入保持。区间完成检查使用原有浮点舍入量。

独立 ROS 仿真的完整记录位于 `output/oscillation_fix/precision/`。
从路径起点运行到终点耗时 260.79 s，采集 130,369 个反馈点：

| 全过程反馈指标 | 测量结果 | 既定上限 |
| --- | --- | --- |
| 路径误差 RMS | 0.11293 mm | 0.15 mm |
| 路径误差 P95 | 0.19850 mm | 0.5 mm |
| 路径误差最大值 | 1.05411 mm | 2 mm |
| 工具轴角度 RMS | 0.03205° | 0.05° |
| 工具轴角度最大值 | 0.20211° | 0.5° |

13,015 个 QP 全部成功。控制步计算耗时 P95 为 10.295 ms，最大值
20.184 ms；一个计算步超过 20 ms，占 0.0077%。20 ms 控制周期能够覆盖
本次测得的绝大多数计算步。速度、加速度及 jerk 均满足配置限值，保持阶段的
速度与加速度收敛至零。

```bash
source install/setup.bash
python3 scripts/validate_tracking_smoothness.py --output output/tracking-smoothness
```

验证创建两个独立 ROS 进程，从路径起点开始跟踪，完成后继续记录两秒保持过程。
输出目录必须尚不存在。记录包含反馈位置、执行器速度、执行器加速度、位置命令、
仿真时间和接收时间；`motion_validation.json` 检查运动限值及最终静止状态。
`sources.json` 保存源文件哈希；控制器和执行器参数分别保存在运行快照及
`plant_parameters.json` 中。命令退出成功还要求控制器的区间覆盖与任务精度通过。

全过程路径误差使用每个反馈点，通过正向运动学得到末端位置，再计算它到参考
路径连续线段的距离。路径交叉处使用连续的投影窗口保持路径顺序。

- RMS：所有误差平方的平均值再开平方，用于表示整个过程的误差水平。
- P95：95% 采样点的误差不超过这个数值，同时保留最大误差供检查。
- 瞬时加速度：执行器在采样时刻直接输出的加速度。
- 区间平均加速度：相邻速度之差除以仿真步长，用于检查采样间的速度变化。
- 速度高频分量 RMS：使用 5 Hz 以上的分量量化快速波动；仅用于统计，
  速度及加速度图片直接绘制原始记录。

`task_verdict=pass`，起点投影为 0，终点投影等于完整弧长

`full_path_verified=false`、综合结论为 `insufficient_evidence`：报告没有

图片采用执行器反馈，控制器报告采用积分后的模型输出。两种测量边界各自使用
全部样本；反馈数据中的五项误差也均满足既定精度要求。全路径声明要求首次
反馈投影位于路径起点，其他起始位姿必须单独核对实际覆盖范围。

## 图片要求

绘图入口将图片导出到 `picture/proposal/`，格式为 300 DPI 的 PNG。
中文采用 SimSun，英文和数字采用 Times New Roman，图中文字不显示具体日期。
运行数据目录中的 `figure_manifest.json` 记录文件哈希、字体文件、分析脚本和
图片说明，`smoothness_metrics.json` 保存完整统计。图片文件夹仅包含 PNG。
图表覆盖全过程误差、九轴运动、局部速度、三维路径、平面投影、工具轴方向、
关节行程、控制计算和精度验收。具体导出文件以生成后的清单为准。

重新绘制当前记录使用本地分析脚本：

```bash
PYTHONPATH= output/proposal_figures_20261019/venv/bin/python3 \
  output/oscillation_fix/analyze_and_plot.py precision
```

该命令使用绘图环境中的 Matplotlib、NumPy、SciPy 和 Pillow，直接读取
`precision/` 下的原始记录；执行器的速度与加速度曲线不进行平滑处理。

这些记录验证的是仿真运动学与控制计算。电机惯量、摩擦、电流、通信延迟和实际
停车能力需要独立实验确认；当前 live 限制继续生效。
