## 实施安排

### 合规性、完成与实际指标

每次运行分别给出`data_valid/constraint_compliant/task_completed/exit_completed/timing_qualified`及原因，整体合格要求全部成立。缺少必要证据标记不可核验，保留该次运行及其失败归属。预先声明的异常处理场景按对应期望核验，单独报告其任务是否完成。

| 指标 | 定义与共同要求 |
|---|---|
| 三类进度 | 保存s_plan及计划身份、M06已结算s_ref及执行区间、实际TCP有序投影s_tool及分支。独立重算完整覆盖、重复/缺失/部分执行和停止余运动。 |
| 路径误差 | cross-track取同一M01连续路径上的有序投影距离；同时记录相同s_ref的三维参考误差、切向进度差及分支有效性。采用#138的cross-track RMS≤0.15 mm、p95≤0.5 mm、max≤2 mm。 |
| 工具轴 | 对同一参考及实际工具`+X`求真实夹角，自由滚转保持独立；RMS≤0.05°、max≤0.5°，暂停/恢复另按各自阈值。 |
| 工具工艺 | 从实际反馈/有来源的重建运动取得TCP速度、加速度、jerk，包含Jdot/Jddot；切向进给导数包含切向随时间变化，路径法向平面量与工件法向量分别报告。逐项遵守M07实际适用上限。 |

M12以物理时间积分形成时间加权RMS和时间加权分位数；同时报告按有序弧长加权的任务质量，二者分别命名。跟踪质量覆盖起步、跟踪、减速、停止、参考暂停、恢复和端点保持，入场/退出另列。无效区间和间断保留其持续时间与原因，不删除后继续报告完整通过。关节和安全条件覆盖全部运行阶段。

覆盖按实际连续有效区间及其有序投影形成区间集合；采样间的重建方法、误差和几何证明具有来源。实际反馈不足时，该段保持未验证。仅到达最后一个参考值、样本数量齐全或首尾位置接近均不能代替完整有序覆盖。

### 共同实验条件与场景矩阵

同一配对条件固定模型、TCP/标定、M01、限制、场景真值、初始状态、五维入场目标、传感器/噪声配置、执行过程、恢复和评价。三方法独立重置plant/设备状态、run_epoch及缓存；方法顺序随机且在30个配对条件中平衡六种顺序。初始化、在线重算和所有失败均记录。

仿真点云由各方法实际构型及相同环境、采样和噪声配置生成，回放绑定对应构型与时间。现场配对在同一已核验设备工况和场景下分组执行，记录日期/设备变化形成统计分组。噪声与动态范围使用具有来源的参数和数据，不将研究采样分布当作设备测量分布。

|---|---|---|

| `surface_static` | 同一曲面上的单障碍、双障碍及关节行程/运动能力受限条件，各自保存配置，保留全身对象和连续可行性，评价受限进给与冗余构型。 | #125/#160/#169 |

消融使用同一MPC和执行保护，分别取消未来构型引导目标、固定上层参考为M01名义进给安排，核验未来构型和进给优化的作用；其余硬性限制、真实参考协调和最终检查保持共同定义。每项保存改变的数学项、配置与预期作用。主比较、消融及异常处理各自保存结果类别。

### 开发、正式重复与统计

参数开发与正式采集使用独立run/seed/data身份。推荐每个正式效率场景、每种方法执行30次独立完整运行，形成30个配对条件；开发使用独立seed组，正式使用固定的1000–1029号配对条件，随机生成器、主seed及生成后的输入清单预先保存。消融同样使用30个共同条件。异常功能矩阵每个规定事件重复3次，按事件结果验收，统计中单独列出。

正式开始前固定全部配置、代码/依赖、场景、种子/顺序、周期/预算、统计方法和容量。正式运行失败保留在原30次中；运行中程序故障、算法不可行、超时、覆盖不足、质量或记录失败均归类，不补充运行替换。设备/现场使整个配对条件无法满足预设输入时，保留原始记录和排除依据；重采按新条件身份登记并同时报告原条件。

每方法报告全部30次的完成/合规/时间通过比例及95%二项区间。效率主要对比为预测协调相对实时协调、预测协调相对逐点IK；只对共同合格的配对比较完成时间，同时列出缺失配对和其原因，完成率使用全部运行。

主要时间指标`T_process`从入场后的STARTUP开始至端点保持完成，包含暂停、恢复和停止；`T_run`从Runtime运行开始至退出完成，另列编译/预热/静态加载和方法准备成本，以及从程序准备至最终完成的总耗时。对相同配对的`log(T_baseline/T_predictive)`求中位数与95%配对BCa bootstrap区间，再对估计及区间端点取exp，报告时间比例；10000次重采样，保存固定rng。从完整配对条件重采样，时间采样点不充当独立重复。[SciPy配对bootstrap](https://docs.scipy.org/doc/scipy-1.15.3/reference/generated/scipy.stats.bootstrap.html)提供共同索引及随机生成器接口。

两侧配对符号检验使用正/负时间差的精确二项检验，零差数量单列；所有差均为零时报告差异0和p=1。主要比较在预先列明的全部正式效率场景中形成一个检验家族，使用Holm校正，家族显著性水平0.05；原始及校正p值同时保存。完成率的精确区间使用[SciPy binomtest](https://docs.scipy.org/doc/scipy-1.15.3/reference/generated/scipy.stats.binomtest.html)，Holm使用[statsmodels multipletests](https://www.statsmodels.org/stable/generated/statsmodels.stats.multitest.multipletests.html)的成熟实现。

共同合格配对少于20时仅给描述性效率结果，并标记比较证据不足；所有30次完成/失败情况仍完整报告。bootstrap退化或独立性不足时保存具体不可用原因，不生成数值置信区间。30为本票推荐的研究重复数，结论由实际数据、独立性和区间支持。消融和附加指标单列，未经预先指定的分析标记探索性。

### 完整周期、共同周期选择与预算

实时周期计时从本周期输入读取/对时/队列检查开始，覆盖任务与限制、共享碰撞查询、QP、Ruckig、参考协调、完整运动/停止检查、准入和命令提交，直至必要记录提交完成。分别记录scene生产、上层MPC、异步队列、真实通信/采用/反馈及实际生效时间；预热、拒绝和异常调用各有原始时间。

正式周期选择使用三方法同一目标主机与执行配置，固定CPU集合、线程数、调频策略、负载、内存/加速器和记录模式。开发记录至少10000个完整实时周期，每方法各自保留全部成功/拒绝与最大工作容量情形；MPC同时保存完整状态装配、导数、求解、原约束复核和计划发布成本。

共同实时周期取满足各方法`p99.9_complete<=0.8*T_lower`、开发最大完整耗时与时钟/调度误差仍在实际生效截止之前的最短整数plant tick倍数。该周期还必须满足已验证的反馈有效性、任务误差、场景/停止及设备保护允许范围。按照候选周期重新运行完整开发检查并固定最终清单；不存在同时满足的周期时保持正式采集不可用。具体tick、误差、周期和最大允许范围均有实际来源，不默认填入未测值。

预测周期和网格由#150测量，结合#142/#151有效期及独立保护确定，保存上层预算与异步相位。正式评价报告p50/p95/p99/p99.9/最大值、超期/拒绝数量与比例、端到端生效及反馈延迟。所有实际采用区间必须在期限内取得完整准入；过期结果拒绝并按Runtime处理。功能故障注入与正常效率场景分别核验其预设结果。

单项solver或query耗时只作为分项证据。仿真物理时间、host真实计算耗时和设备时钟保持独立；加速/暂停仿真不改变host预算判据。正式主机或CPU条件改变时建立新配置身份并重新取得完整周期证据。

## 供 spec 采用的要点

- 三方法共用当前九轴蝴蝶任务、实际工艺与执行规则，全部运行保留合规、完成、时间及失败结果。

- 共同周期依据完整组合、目标主机、最大工作容量和物理有效范围选择，采用结果必须满足期限。
- 正式清单、数量/存储上界、可重算记录及复现由#169统一验证，理论与性能结论声明证据范围。
