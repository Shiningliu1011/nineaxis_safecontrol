## 实施安排

### 模式、状态与写入归属

| 对象 | 推荐规则 |
|---|---|
| `RuntimeStatus` | 保存`run_epoch/mode/phase/phase_seq/phase_started_ns`、加工许可、完整M07检查、当前State/scene/plan/command及错误原因。Runtime独占阶段写入。 |
| `FeedbackEvidence` | 保留各关节原始反馈、设备身份、关节映射、时间映射、q/qdot/qddot来源、有效区间与误差、驱动状态和保护状态；M05在共同有效时刻形成State。 |
| `AdmissionResult` | M10绑定最终Ruckig关节运动、协调参考、全部分段与停止、状态/场景/参数身份、期限和检查结果；保存允许采用的具体区间。 |
| `ExecutionReceipt` | M11区分请求、设备接收、实际采用和有效执行证据，保存拒绝/部分/重复/失序；M06按#141独占结算。 |
| `StopEvidence` | 分别保存软件停止请求、已检查停止轨迹、保护链动作及实际停止反馈；包含测量方法、关节速度/加速度范围、保持时间、误差和适用负载。 |
| 模式配置 | sim使用实际仿真plant及共同仿真物理时间；shadow维持当前只记录、无CAN收发、无硬件健康/执行证据；live依赖完整设备准入及具体现场授权。 |

所有对象采用#142共同身份、不可变记录与int64 ns物理时间。host单调耗时单独保存，仿真物理时间允许从0开始。实际控制模式和命令能力由设备资料与接口验收确定，位置或速度模式、插补、缓存、接替和停止行为均不得由软件字段名称推断。

### 阶段及共同工艺检查

Runtime使用以下阶段identifier；M07的阶段通过固定映射调用，配置中保存映射身份。M07当前共同阶段名称为小写，映射明确使用`tracking/paused/recovery`等已有名称。

| Runtime阶段 | M07阶段 | 准入、动作与离开条件 |
|---|---|---|
| `INIT` | `initialization` | 验证配置、模型/路径/标定、反馈与时间映射、场景、能力、预算及记录容量。具有运动时取得并执行已检查停止，登记实际初始停稳构型；全部条件有效后进入入场。 |
| `ENTRY` | `entry` | 加工关闭、参考为0；按#140规划并执行五维首目标连接。到达、停止及位置≤0.3 mm/工具轴≤0.04°后连续观察2 s，期间所有必要条件有效。 |
| `STARTUP` | `startup` | 从实际关节及参考导数连续生成获准加速运动；加工许可由当前工艺检查决定。实际完成启动区间后进入跟踪。 |
| `RUNNING` | `tracking` | 三种方法均读取同一有效State、M01和限制；M10检查实际运动与参考后执行。超出位置1 mm或工具轴0.2°的M07暂停阈值时停止继续加工推进，进入受检减速/停止过程。 |
| `DECELERATING` | `deceleration` | 根据当前任务、端点或暂停请求生成连续减速；采用的剩余运动和参考继续由M06结算，全部工具与机械限制持续检查。 |
| `STOPPING` | `stopping` | 执行具有当前有效证据的停止全过程，保存余运动和参考；实际停止条件及参考导数归零通过后进入等待、终点或故障处置。 |
| `REFERENCE_PAUSED` | `paused` | 参考保持、加工关闭；保留已结算进度，等待场景与计划，检查有效保持及等待期限。存在可行恢复动作时进入恢复。 |
| `RECOVERING` | `recovery` | 参考保持，允许完整准入的构型调整；位置≤0.3 mm、工具轴≤0.04°、可行正向候选及全部状态条件连续满足0.2 s后进入连续加速。 |
| `ENDPOINT_HOLD` | `endpoint_hold` | 参考到达1，实际有序覆盖完整、端点位置≤0.5 mm/工具轴≤0.5°并实际停止，全部条件连续保持0.5 s后结束加工并进入退出。 |
| `EXIT` | `exit` | 加工关闭，从实际状态按最新场景重新规划至登记的初始停稳构型；完整连接、停止与最终反馈有效后完成。退出失败保存实际状态并报告未完成退出。 |
| `FAULT` | `fault` | 保存首个及后续原因、实际已执行区间、停止请求与证据；停止加工许可，拒绝无证据的新运动。只有恢复准入及人工确认通过后重新初始化。 |
| `COMPLETED` | 结束记录 | 保存最终状态、覆盖、保持、退出和完整评价；没有后续执行区间，任何新运行建立新代次。 |

参考误差暂停条件和M07检查结果共同约束`can_continue`，不得在已经要求暂停时继续报告跟踪可继续。零进给等待、恢复构型调整、加工许可及实际覆盖分别记录；停止请求后的实际余运动保持原时间和命令身份。

加工中所有阶段遵守#138共同机械和工具上限；入场、退出、恢复、停止使用其对应M07阶段。暂停/恢复等待累计上限30 s；阶段往返不重置本次等待，成功恢复后才结束该次等待。研究总时限420 s，自本次运行开始计入初始化、连接、加工、等待、停止和退出，时钟、预热与计算准备另外保存原始时间；正式采集边界由#144确定。实际停止速度、加速度和持续时间判据保存到版本化设备/仿真配置，缺少必要依据时对应模式不可准入。

### 最终运动、执行与异常

1. M05提供有效State，M09按实际生效时刻使用有效计划或独立模式输入。M10从可验证起始状态生成真实Ruckig运动及#141变速参考，检查关节、实际TCP高阶运动、五维误差和阶段条件。
2. CollisionSafety对当前scene及请求时间检查完整运动和停止。每个构型使用自己的时间；scene、query、运动和覆盖证据的身份及整个有效区间相容，保留连续区间证明与容量/时间结果。
3. 检查反馈/估计、时钟映射、设备能力、物理有效区间、当前计算deadline和预计生效时刻；所有必要条件通过后，M11接纳具体的共同区间。
4. M11提供实际采用及执行证据，M06结算连续有效区间，M05/M08/M09/M12读取结果。请求未采用、执行证据缺失或部分执行均沿用#141规则，不能按计划长度累计。

| 异常 | 处置与恢复要求 |
|---|---|
| 计划失效、求解失败或超过预算 | 该候选不可采用。若共同配置允许独立运行且最新状态、场景、截止条件及完整新运动均通过，可由独立M09生成候选；否则执行当前仍有效的受检停止。模式切换和原因保存。 |
| 已采用短段与新场景冲突 | 重新核验剩余运动及停止；只允许仍具有完整有效证据的区间继续执行。已发布的旧证明不自动延长有效期。 |
| 命令迟到、拒绝、部分执行、接替失败 | M11报告实际采用事实，M06结算已确认部分；后续状态由真实反馈重建，重新检查新运动及停止。 |
| 无效反馈、通信中断、时间映射异常、驱动故障或急停 | 停止生成依赖无效状态的新运动，触发已验证的设备保护策略，锁存原因。缺少状态时报告实际停止未知，由独立保护链和后续有效反馈提供证据。 |
| 无法证明当前停止运动 | 报告准入失败并请求已验证的独立保护；不能通过软件阶段名称、保持位置请求或人工acknowledgement宣称已经物理停止。 |
| 模型/配置/时钟变化或重新启动 | 原待执行计划及证明失效，建立新代次，保留最后已确认历史；从有效实际状态重新初始化，重新核验停止、场景及入场。 |
| 故障后人工确认 | 人工确认只解除相应锁存请求；设备健康、反馈/时钟、实际停止、场景与完整新运动仍需独立通过，旧命令不能自动恢复。 |

临时碰撞等待与需要人工处理的故障采用明确原因分类。可恢复等待持续受到30 s及总时限限制；保护动作失败、无法约束反馈或设备状态异常进入故障。上游输入错误立即在其接口拒绝并保留原因，Runtime在受控边界执行上述处置。

## 供 spec 采用的要点

- Runtime阶段、M07适用限制、加工许可和时间条件具有明确映射及记录，三种方法共用。
- 反馈、估计、最终运动、参考、scene、保护、采用和进度都保留来源、身份及有效区间。
- 实际Ruckig运动与停止、工具高阶运动及整个未来场景证明共同决定执行准入。
- 计划失效、计算失败、执行拒绝、无效反馈及重启分别处理；只执行仍具有当前证据的区间。
- 软件请求、设备保护和物理停止分别核验；现场参数与live准入依据对应实现、独立测量及具体授权。
