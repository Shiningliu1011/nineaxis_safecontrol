## 实施安排

### 共同身份、单位和不可变记录

采用版本化、不可变的共同对象。计算接口遵守[项目单位](../../units.md)：J1使用m，其余关节使用rad，位置/速度/加速度/jerk分别带对应SI时间量纲；位置、轴向及标量进度分别保存。用户文件和报告使用mm/°并在边界明确转换。

共同头部为`schema_version/run_epoch/task_id/model_id/path_id/config_id/clock_id`与内容hash；clock映射、TCP/工具、标定、场景/geometry/policy及求解版本通过明确字段或manifest绑定。`run_epoch`表示一次连续执行代次；重启、时钟重建或不能连续核验的恢复建立新代次。序号在自己的owner内严格递增，内容改变即改变hash。

| 对象 | 内容、维度与写入归属 |
|---|---|
| `CommonConfig` | M01/M02/M07及运行配置的版本引用、关节名/类型/顺序、N和各容量、模型表达、阶段、TimingPolicy、状态相容阈值及全部来源。配置loader创建，启动时验证完整性，各模块只读取。 |
| `State` | M05独占发布。包含`state_seq/state_time_ns`、q/qdot/qddot及各量来源、采样时间/有效区间/误差/availability；当前阶段、M06的s_ref/nu/nu_dot和已结算区间、s_tool与分支/投影误差、最近采用命令及执行记录、scene身份与时间。当前九轴数组最后一维9。 |
| `UpperPlan` | M08独占发布。包含`plan_id/source_state_seq`、生成起止及发布时间、`t0_ns`、严格递增的N+1个节点时间、N个控制区间、有效起止及N上限；保存N+1组q/qdot/qddot和s_plan/nu/nu_dot、N组可重建的关节及参考运动表达、模型/控制语义、阶段和各节点场景检查身份。 |
| `LowerResult` | M09独占发布。绑定State、采用的plan_id/区间或独立模式来源、候选运动和参考、实时修正、任务/工艺/关节/碰撞残差、solver状态、耗时及内容hash。求解成功、M10准入和M11实际采用分别保存结果及关联身份。 |
| `ScheduledMotion/ReferenceSegment` | 沿用#141共同区间、真实分段、导数、停止后续运动、阶段与命令身份；M10根据最终运动协调和复核，M11只接纳有效调度。 |
| `ExecutionReceipt/ProgressLedger` | M11发布实际采用且有执行证据的区间；M06独占结算。重复、部分、缺失、乱序、重启等沿用#141。M05/M12读取带有效时间的结果。 |
| 记录和回放 | M12保存原始输入、所有候选/计划、准入/采用/拒绝、配置和代码来源、各时钟时间、原始反馈及逐字段有效性，并从相同分段独立重算。 |

State的“同一时刻”由明确的重建过程取得：各反馈保存原始采样时间，通过具有误差界和有效区间的插值或状态估计形成共同`state_time_ns`。qddot区分测量、估计及其来源；缺少可用加速度时，依赖该量的求解或准入拒绝。命令及预测值保留其语义，反馈有效性由实际来源提供。

UpperPlan的模型及控制语义由#150确定，并登记维度和从控制区间重建状态的方法。共同表达始终能够核验q/qdot/qddot、s/nu/nu_dot及所需jerk；优化器内部变量与物理运动之间使用显式转换。节点数组、区间表达及起终导数一致，归一化进度使用同一M01总长和路径身份。#150可以选择均匀或非均匀网格，各段长度为严格正整数ns，全部保存。

### 物理时间、耗时与期限

| 时间 | 表达及检查 |
|---|---|
| 共同运动时间 | 使用int64纳秒和`clock_id/run_epoch`。仿真使用共同仿真物理时间及tick→ns定义；单机真实执行使用明确的host/device单调时钟。所有观测、状态、计划、运动、场景和执行区间进入同一物理时间域。 |
| 设备、ROS、LiDAR原时间 | 原始数值/单位和时间域完整保存，经版本化`ClockMapping`转换。记录有效源区间、比例/参考点/误差、同步来源、更新时间与适用期限；映射不足、回跳或无法约束误差时拒绝依赖输入。epoch FLOAT64 ns的量化误差须计入。 |
| 计算耗时 | 使用执行计算所在主机的单调计时，保存开始、结束、队列等待与host身份。仿真暂停时仍可检查真实计算耗时；两个主机的耗时记录分别保留。 |
| freshness | 核验采用时刻所需反馈、场景、映射和估计是否仍有效，误差覆盖至预计生效时刻。 |
| 物理有效区间 | 计划、参考、运动、场景tube和覆盖分别保存起止时间，整个请求区间包含在所需有效范围内。 |
| 计算deadline | 分别登记采集/传输/排队/预测/实时求解/运动生成/连续复核/下发的预算与来源；在实际命令生效截止之前完成全部必要环节，计入映射和调度误差。 |

绝对时间在host边界以int64保存。求解器按相对于`t0_ns`的秒处理有界时长，输出时检查范围和量化误差；禁止以巨大epoch浮点秒进行相减来计算短控制区间。区间采用`[t_start,t_end)`；整个运行和最后保持的边界单独定义，终点时刻不得自动成为新的控制区间。

TimingPolicy明确`feedback_period_ns/lower_period_ns/upper_period_ns`、各阶段deadline、freshness、乱序缓冲/等待容量、状态预测范围及其来源/验证状态。已有S0的100 ms控制和2 ms仿真推进保持其来源身份，完整项目周期通过#150选择与测量、#151执行准入、#144/#169正式判据共同确定。参数缺失的模式保持不可用；独立模式和预测协同分别声明所需字段，已证实的物理约束及计时边界持续适用。

### 按生效时刻采用计划

1. M05依据实际反馈和M06最后确认区间建立有效State。M09/M10确定拟生效时间`t_effect_ns`，用当前已采用运动或具有误差界的估计重建该时刻状态，同时保存原始反馈时间和估计范围。
2. 检查UpperPlan的代次、任务、模型、路径、配置、时钟映射、内容hash、scene及生成/有效区间；按`t_effect_ns`选择唯一的`[t_k,t_k+1)`。计划可以跨越多个实时周期，按实际生效时刻查询区间内连续运动及参考。
3. 用同一时刻的实际重建状态与计划状态核验关节位置/速度/加速度、s_ref及参考导数、阶段和历史接续。阈值来自版本化TimingPolicy/M07及估计误差；缺失来源或超出范围使该计划不可用。求解起点和最后采用结果变化后重新检查。
4. M09以最新实际状态和约束生成候选；M10对最终Ruckig运动、变速参考、当前scene和停止重新检查。UpperPlan的检查身份及M10的当前检查分别保存。
5. 只有M11实际采用并提供执行证据的区间进入M06结算。下一次预测从最新有效State滚动更新；采用结果、实时修正及拒绝原因同时反馈给M08和M12。

### 异常、切换与恢复

| 情况 | 处理 |
|---|---|
| 完全相同plan_id和内容hash再次到达 | 幂等读取，保留原生成时间和有效期。 |
| 同身份不同内容、非法shape、非有限、负区间或节点/连续表达不符 | 输入立即拒绝，记录具体字段与原因。 |
| 旧plan_id晚到、已过期、起点超出可验证预测范围 | 标记不可用，保留原记录。 |
| 新计划接替 | 在实际生效边界核验共同状态、参考、阶段及停止接续；M10验证最终运动。计划建议和已采用运动各自保留身份。 |
| 反馈/ledger/场景缺失，时钟映射改变或预算耗尽 | 对应状态和计划不可用，输出明确原因；Runtime按#151和#143选择允许的独立运行或已检查的停止。 |
| restart、模型/路径/配置变化 | 旧待执行计划失效，建立新代次及有效State；依据实际反馈和#141已确认记录重建接续，重新完成准入。 |

State及计划状态包含明确availability、reason和有效时间。缺少必要反馈或执行证据期间保持最后确认历史及其时间，后续模块依据有效性处理。Runtime负责模式和阶段，M08/M09负责候选，M10负责准入，M11负责执行，M06负责进度，M12负责记录与独立评价。

## 供 spec 采用的要点

- State反映共同有效时刻的反馈、估计、执行参考和工具投影，各项具有来源、误差及有效期。
- UpperPlan具有完整身份、N+1节点/N区间与可重建的运动参考表达，按实际生效时刻采用。
- 物理时间、原始设备时间映射和计算耗时分别定义；绝对ns及相对秒通过明确边界转换。
- 计划、候选、最终运动、准入和执行记录各自保存内容身份，只有有效执行区间进入M06。
- 模型、周期、期限、模式和独立回放按现有任务取得验证证据，配置缺失或过期时明确拒绝依赖功能。
