## 实施安排

### 九轴共同模型接口

| 对象 | 必需内容与行为 |
|---|---|
| 九轴模型配置 | 模型 ID、URDF/SRDF/mesh 校验身份、`J1`–`J9` 顺序、1P8R 关节类型、坐标根、工具 link、固定附属几何及其状态；共同接口校验九维输入 |
| 坐标与工具 | 明确属于 SE(3) 的 `T_base_workpiece`、模型工具变换及 TCP 标定修正、TCP 局部工具轴、单位与标定版本；仿真资产缩放独立登记，正运动学和碰撞几何使用同一刚体变换链 |
| 运动学求值 | 对 SI 的 `q` 提供各 link 与 TCP 的位姿、位置和角速度 Jacobian、工具轴及其 Jacobian；提供实际工具速度、加速度与 jerk 所需的方向导数 |
| 预测消费 | JAX 与预测模型使用同一关节链、TCP 和坐标定义；求解后用共同模型复核原始任务与几何约束。后端形式由 #150 确定 |
| 几何消费 | 按 link 身份提供碰撞变换、mesh 来源、固定几何及自碰撞检查列表；模型、工具或标定改变后，关联几何与计划需要重新取得有效性证据 |
| 限制消费 | 关节类型和单位来自九轴模型配置，位置与运动限制带来源和适用状态；M07 管理运动与工艺数值。缺少必需参数时明确拒绝相应运行 |
| 标定输入 | 分别记录 TCP、工件、传感器、设备关节映射与零位；每份记录包含源坐标、目标坐标、单位、模型身份、测量方法、残差和验证状态 |

控制内部使用 m/rad/s；输入、展示和报告使用 mm/°/s。速度、加速度及 jerk 在接口边界采用相同长度或角度换算倍率。

### 九轴 TCP 与源工具轴

- 九轴名义 TCP 采用现有 URDF `tool0`。其 235 mm 延伸已经包含在模型中。真实 TCP 修正由标定输入给出并具有独立身份。
- 源路径的位置与轴向先通过明确的工件变换进入机器人基坐标。源 `R_WT` 的第三列表达源工具 `+Z`；给定执行轴与原始表面法向分别保留。
- 机器人模型声明 TCP 局部工具轴。九轴采用当前 `+X`，比较目标为该轴经正运动学映射后的基坐标方向。
- 九轴使用源完整旋转作为 IK 初值或姿态参考时，采用 `C_source_tcp = Ry(-π/2) = [[0,0,-1],[0,1,0],[1,0,0]]`，计算 `R_base_tcp = R_base_workpiece @ R_WT @ C_source_tcp`；该式将当前局部 `+X` 映射到源执行轴 `+Z` 所在方向。五维任务继续保留绕工具轴的自由度。
- 标定测量、关节正方向、真实反馈和停止证据由 #165 及相关现场任务提供。仿真模型记录自身参数来源与验证范围。

### 独立验收

1. 从原始 URDF/SRDF 和 mesh 核对关节顺序、类型、单位、限制、固定关节、TCP 与碰撞对象，保存来源与校验值。
2. 对零位、合法初态、行程内部状态及限位附近状态，逐轴比较共同模型与独立 URDF/MuJoCo 求值的 FK、工具轴和 Jacobian。
3. 对每个受控关节及运动方向独立检查 Jacobian 和高阶方向导数，覆盖 TCP 修正与工件变换；阈值区分平移、旋转及各阶导数的单位。
4. 同一 `q` 下核对控制、预测、MuJoCo 和碰撞几何使用的 TCP 与各 link 变换；核验模型或标定身份变化时的拒绝与重新加载规则。
5. 核验九轴模型的合法初态、完整工具几何、自碰撞、可达任务及三方法共同输入。运行证据记录九轴模型配置和源资产身份。
6. 实际 TCP、工件与设备参数通过现场独立测量验收；本轮模型数值检查仅支持所检查的模型和状态。
