### 已接受：按失败原因处理，优先保留完整任务

研究后不再要求每次固定执行“细分→缩域→换姿态”。具体构型已相交时直接调整该候选；点分离但区域界不足时，先利用相对运动改善界，再有预算地细分；额外活动范围导致失败时可以缩域，保留必要误差/反应/停车空间和路径连通性。参数缺失或预算耗尽明确记未知。省略非相邻对按既定方案评估补约束，但补对不能使相交构型通过。方法、源码证据及 252 个新配对点检查详见研究记录。

若仍不能覆盖完整任务，交付反例或“无法证明”的证据，分别记录已证明局部区域和未覆盖段。下一步再就缩短/改变任务或修改碰撞表示作具体决策。此路线优先保留任务完整性，可能增加筛选与验证工作。

### 已接受：OFF-02 向 OFF-09 输出双评估强绑定状态

经[接口研究](../research/off02-off09-interface-20260915.md)修订，OFF-02 不输出一个含义过宽的 `geometry_ok`，也不只传两个裸枚举。建议分别输出：

1. 点碰撞评估：`separated / overlap / indeterminate`。绑定确切 q、`J1`…`J9` 顺序、查询 ID、测量边界、全部非相邻配对策略和模型身份；相邻 9 对免检。原则上点查 36 个非相邻对；若不能全查，运行检查与证书覆盖的并集必须无缺口。
2. 任务域证书评估：`covered / outside / indeterminate`。绑定本次所需动作/停车包络、证书 ID、模型/附件/任务身份和证书负责的配对集合；只检查一个点不能产生 `covered`。

OFF-09 只有在点状态为 `separated`、区域证据为 `covered`，且查询、边界、配对和身份完整一致时，才能把几何分门视为通过，再与求解器、原约束残差等门串联。其余状态均拒绝并进入 OFF-09 已定的冻结锁存；OFF-02 只提供几何事实和稳定原因码，不拥有锁存或人工恢复。

当前 `TrackingStepData.overlap` 是 `bool | None`，报告为 `overlap / clear / unmeasured`，可保留为评价投影，但不能作为上述运行契约本身：它没有表达测量边界、配对完整性、域外、证书身份失效或仅点检查通过。具体类型、传输和性能优化属于实现阶段；语义先在本决策点确认。

## 实施结果

[OFF-02 局部证书报告](../research/off02-local-certificate-20260915/REPORT.md)已交付 36 对独立点判据、22 对相对运动连续界、已知盲点回归、模型/配对/证书身份及确定性证据生成器。固定起点至当前蝴蝶首点的拟议直线关节过渡盒已获得模型内局部证书；完整蝴蝶跟踪、生产 MoveIt 过渡和物理误差/停车包络仍明确为未知，局部结果不升级为完整任务 `covered`。

## 排除项与证据限制

本轮没有重新开放既定总体路线，也未启动 ROS、MuJoCo 或真实硬件。无真实硬件、最终阈值、完整实机运行域认证；全关节域随机起点不作为首轮已覆盖能力。详细数据核对、输入哈希、源码证据和未知项保存在局部证书报告及 JSON 证据中。
