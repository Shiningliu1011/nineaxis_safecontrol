## 已确认的事实与尚缺证据

原生依赖仍开放：回归剖面与成本分布测量、感知时间同步与延迟模型、自碰撞 OBB 与环境几何模型核对、真机执行链路 SocketCAN 后端与参数注入。没有撤销依赖或将阶段报告计为验收。

当前 YAML 配置 `publish_frequency_hz=100`、`dt_path=0.01`；节点 `latency_budget_ms=20` 是历史性能报告口径。配置周期、单步计算分位数、端到端反应上界是不同量。历史 50 Hz/20 ms 与 miss≤1% 不升级为全局实时保证，也不为了通过测试修改阈值。

节点 `_step_durations` 计时包含 `step_once` 及内核输出主机转换；不包含后续评价、日志、低通、ROS 发布、CAN 和电机响应。发布前 `tau=0.02 s` 一阶低通使用配置周期，实际动态必须由最终执行轨迹验证；不能直接把 tau 当成固定运输延迟，也不能认为内核安全命令等于实际执行命令。

硬件桥当前把命令产生时刻和反馈时间改为接收 `now`，无独立断流检查；9轴串行每轴10ms读取产生约90ms源码等待预算，尚非实测时延。现有 latency 指标是反馈轮间隔。见[SocketCAN 核验](13-socketcan.md)，不以0.2s参数代替已验证期限。

[感知时间模型](7-perception-time-model.md)尚缺可信时钟映射与逐贡献源采集起点；[几何核验](8-obb-environment-geometry.md)仍有距离/导数反例、Link6覆盖和附件缺口；实际制动、载荷、速度与独立看门狗证据未齐。降频本身不能修复这些正确性问题。

## 预算草案：按事件区间计时

事件线：可信采集起点 → 控制消费 → 最终命令校验/发送 → 执行器开始制动 → 完全停止。

对必要覆盖的实际贡献源 i：

`A_i = t_consume - t_acquisition_start,i + epsilon_clock,i`

先检查时钟域、会话、未来/零/非有限时间的有效性；不能用钳零掩盖失效。

`B_i >= d0 + epsilon_geometry,i + Reach_relative(A_i + T_consume_to_brake) + D_stop`

- `B_i`：对应工况可用保守间距；不是原始最近点距离。
- `A_i`：消费时刻的观测年龄，已经包含消费前采样/处理/排队，不再加一次。
- `T_consume_to_brake`：消费之后至制动开始的非重叠时间区间，包括剩余几何/求解、拷贝、调度、最终命令处理、ROS/CAN及执行反应。若测量段已包含拷贝，不再加同一拷贝。
- `Reach_relative(t)`：适用速度界恒定时为 `v_relative_bound*t`；否则用经验证的可达位移界。未知速度不能当0。
- `D_stop`：制动起始之后机器人与障碍的相对位移；避免和前述时间项重复。

这是预算核算草案，不是现有系统安全性证明。样本 p95/p99/max 用来比较性能，不能作为故障条件下的上界；看门狗触发及实际停止必须独立实测。

## 可审阅的推进方案

推荐先对**约束构造**做保持覆盖和数值语义的离线优化对照，保留现有 JAX/cbfpy/qpax 及 OBB 表示作为基线；使用同样场景验证几何正确性、导数、QP状态、任务效果及尾延迟。暂不通过更换求解器或删障碍行追求10ms，因为当前成本证据不支持其优先级。

后续实现提案应明确：可复用的已有几何/导数接口、必要最小适配、独立解析/FCL对照、动态启用/停用与容量验证、固定基线和回退。若收益不足保留原实现。具体生产接入沿用[控制模块复用与九轴适配](https://github.com/Shiningliu1011/nineaxis_safecontrol/issues/32)，不另建同义票；新优化实现票须在用户选择路线后再创建并接原生依赖。

需用户决定的是优化实施优先路线；不要求用户凭空填写尚无证据的安全毫秒数。最终生产周期、GPU准入、命令期限和观测年龄阈值需待上述前置闭合后再形成有数字的选项。本轮不改变配置、不启用真机、不关闭本票。
