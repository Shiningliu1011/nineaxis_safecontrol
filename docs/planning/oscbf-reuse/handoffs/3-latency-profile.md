## 测量结果

当前生产构造模式 elastic、CPU/x64、仓库蝴蝶轨迹300步理想反馈回放：外障禁用 p95 **8.495ms**，八槽远障启用 p95 **12.444ms**；后者300步全部超过10ms，四组共1200步均未出现QP失败。这不是全轨迹、实机或持续最坏负载验收。

rate_slack候选相应 p95为 **8.881/13.205ms**。冻结问题是11变量、81不等式，纯qpax求解p95 **0.199/0.160ms**。默认elastic与rate_slack是不同控制语义，不以这组结果决定替换。

独立模块探针表明主要成本在 `_path_constraint_terms`；禁用外障的elastic构造p50 **6.450ms**，对应 `_path_solve` p50 **0.335ms**。模块单独dispatch会改变融合与同步，其分位数不能相加当成原始内核分布。拆分所有输出与融合输出在rtol=atol=1e-7一致。

源码及实测确认 `collect_cbf_diagnostics` 不控制 `path_tracking_step`：True/False均走同一函数。不能把两轮测量的差异解释为优化收益。完成同步后，主机诊断p50约0.29–0.41ms；输入准备启用八槽时p50约1.07–1.13ms。降低遥测成本可能有收益，但优先级低于约束构造。

`init_cbf`外层计时包含构造/编译/预热/同步：elastic **33.342s**、rate_slack **20.973s**；内部预热打印约16.8/16.7s，是不同边界。没有伪称这些秒数是纯JIT编译时间。Python发布探针独立测序列化与API返回，详情见表；不能当DDS/CAN/执行器端到端时延。

## 按候选收益排序的清单（待决策，未实施）

1. **约束构造与几何导数**：优先定位并验证保留覆盖的计算复用、消除重复运动学/导数计算和已知几何修复的性能；可作用于约6–9ms级成本区间，但具体收益未测，不承诺百分比。保留OBB表示；独立解析/FCL对照及Link6/附件覆盖问题仍由几何原票持有。不能为提速删行或把启用障碍改成禁用。
2. **输入准备与诊断回传**：在显式更新/失效契约下复用设备缓冲、合并主机输出；目标是当前约1ms输入准备及亚毫秒主机诊断成本。现有默认缓存和外层JIT已经存在，先比较收益，不重复实现。真正在路径入口分离可选诊断需证明不删除关键故障判定，开关本身目前无效。
3. **GPU后端**：同版本、x64、相同输入并计入主机边界后才判断；驱动可见不足以证明收益，详见后续GPU证据节。生产准入还缺组合负载、故障响应和端到端执行证据。
4. **换求解器/自研求解器**：当前纯qpax仅约0.15ms级，收益空间低，且引入数值和维护成本；保留成熟qpax，当前证据不支持优先替换。冻结求解不是完整路径成本的替代。

继续直接复用已固定的JAX/jaxlib、cbfpy、qpax和已有冻结QP接口；原型只做同步包装及计时，没有摘录/改写上游求解器。版本见metadata。外部框架新的兼容性/许可证调研不在本轮新增事实范围；既有复用决议继续有效。

## GPU 同精度补测

[CPU/GPU对照表](../research/3-latency-evidence/GPU-COMPARISON.md)及原始结果已完成。RTX3060 Laptop、独立CUDA环境、相同JAX0.6.2/x64/300步：elastic无外障/八槽远障p95为17.415/19.634ms；rate_slack为16.761/19.240ms，四组均慢于CPU。GPU设备驻留内核也更慢，不能将差距全部归因于拷贝。GPU初始化总耗时82.822/54.107s，不计入稳态分位数。

CPU/GPU合计2400步未出现QP失败，八组拆分/融合探针输出一致，两个后端测量前后产品源码hash一致。跨后端回放终点进度存在差异，尚未通过完整命令/任务误差等价门；没有将GPU加入生产链。GPU候选在本轮配置下无替换收益，建议继续CPU基线和约束构造优化验证。组合负载、近障/不可行、真实执行期限仍待补证。
