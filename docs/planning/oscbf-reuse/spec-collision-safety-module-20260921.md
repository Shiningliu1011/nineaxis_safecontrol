# CollisionSafety 统一碰撞安全模块规格说明书

**状态**：本页维护 CollisionSafety 的当前要求索引与实施责任。具体需求和验收以 [DCOL 碰撞核心与双传感器规格 #196](https://github.com/Shiningliu1011/nineaxis_safecontrol/issues/196)和[模块边界、复用与实现清理规格 #197](https://github.com/Shiningliu1011/nineaxis_safecontrol/issues/197)为准，实施共用[完整项目地图 #147](https://github.com/Shiningliu1011/nineaxis_safecontrol/issues/147)。

## 要求来源

用户当前确认在对应范围内优先。#196 管理碰撞几何、双传感器、DCOL、连续证明与周期，#197 管理 OBB 选择、模块边界、公共复用、入口与清理；完整作业规则由[总体规格 #145](https://github.com/Shiningliu1011/nineaxis_safecontrol/issues/145)管理。本页只引用这些要求，验收编号分别使用 `#196:Txx` 和 `#197:Txx`。

| 事项 | 当前要求 |
|---|---|
| 机器人几何 | 采用 OBB，证明完整包含原始 collision mesh 实体；当前十个本体 link 检查 36 组非相邻对象对，工具及附件按实际归属扩展。 |
| 环境几何 | 固定实体与双源观测取并集；OctoMap 占据叶单元以完整凸盒参加查询，合并保留完整覆盖、误差与来源。 |
| 碰撞数学 | 自碰撞与环境碰撞共用几何外扩后的 DCOL `h=alpha-1`；要求间距分别为 10 mm 和 30 mm，各项误差分项计入一次。 |
| 后端与导数 | OSCBF 保留 JAX 框架；碰撞后端采用经过数值、导数和完整周期验证的实现，可以使用 JAX 或 CPU/C++。 |
| 双传感器 | Livox MID-360S 与 Orbbec Gemini 335L 安装在外部固定共用支架，分别保存采集时间、射线起点、标定与观测身份；采用 PCL 和 OctoMap。 |
| 场景与覆盖 | `collision_scene_server` 唯一发布不可变场景，维护 `occupied/free/unknown`、动态范围及有效覆盖；单源失效后按剩余来源能否证明完整必要空间覆盖处理。 |
| 公共接口 | 规划、控制、执行共用 `prepare_scene/query/certify`；每个有效 primitive pair 保留独立约束行、导数、残差、状态和身份，碰撞行不可松弛。 |
| 连续运动 | 当前状态、预测状态、实际执行区间及完整停止采用相同几何、场景与物理时间；无效、超期或证明不足的结果不能获得准入。 |
| 控制周期 | 由目标设备完整测量和物理限制确定；至少 10,000 个完整周期满足 `p99.9_complete <= 0.8 * T`，并核验最大耗时、实际生效期限及设备条件。 |

## 完成与证据

碰撞验收逐项采用 #196 的 R01–R10、T01–T17；模块职责与复用采用 #197 的 R01–R10、T01–T09，其中共同碰撞对应 `#197:T06`。参数、输入、模型、几何、标定、后端、代码及设备身份随实际结果保存。

必要功能经替代实现和对应运行模式验证后，按 #197 清理已被替换且没有独立用途的业务实现。正式 AEB-RRT*、公共运动、独立数值验算及原始研究证据保持各自用途。Ruckig 当前保留必要功能，取消条件采用 #197 I08。

规格确认、源码实施、数值验证、仿真和在线现场验收分别记录。既有完成记录只证明其声明范围；每项当前要求需要对应证据。
