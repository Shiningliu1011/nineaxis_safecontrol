## Question

复用后的感知→求解→发布→CAN执行，怎样证明反应满足任务要求？沿用现有失败锁存要求，重审陈旧阈值、零速实际含义、执行端停止距离、CBF 后命令滤波/积分、实际反馈与内积分状态、任务与避障冲突优先级。

验收场景包括静止障碍跨过确认阈值、新障碍突入、遮挡/空帧/单传感器故障、错误 TF/时间戳、槽位溢出、QP 不可行以及执行延迟。要求目标机器上的延迟分布、deadline miss、几何覆盖和任务偏差证据；不套用上游演示的频率。不在本票凭空确定人体速度/裕度。

复用原“选定不可行/裕度/降级策略”和“选定控制率/延迟预算与实现策略”已有结论；新增内容只作为其跨链路补充，避免双重权威。

## 当前约束与待决取舍

本票已本地领取，未远端领取。核对本地历史记录发现：“选定控制率/延迟预算与实现策略”记录了 50 Hz / 20 ms、miss≤1% 的历史性能口径；“选定不可行/裕度/降级策略”仍为 ready-for-human，不能称其失败/松弛取舍已经确认。前者不直接作为双传感器到实际制动的完整时间上限，也不能将历史 miss 比例解释为允许过期命令继续执行。旧票参考见[重梳说明](../REBASE.md)，本轮不伪造远端最新状态。

沿用[感知输入失败策略](../../../adr/0003-perception-input-failure-strategy.md)与[标定来源权威](../../../adr/0004-calibration-ssot-sensor-extrinsics-authority.md)。默认 CBF 松弛、QP 后位置低通和执行动态意味着 QP 输出可行不等于最终执行满足同一约束。

需要决策的是如何分配全链路延迟与误差预算，以及任务跟踪和避障冲突的处理；严格约束与允许松弛必须有明确适用模式和可观测故障状态。推荐对实际下发和反馈行为设置验收门，具体阈值复用既有决议并由目标机器测量补足。

## 本轮提案：任务让步与故障停止（待用户答复）

用户提醒本机为九自由度冗余机械臂，并要求研究后再判断。本轮提案尚未接受；研究需区分“利用冗余保持工具任务并避障”“任务与安全确实不可兼容”和“关键输入/求解故障”，不得将遇到障碍直接等同必须暂停任务。已有冗余策略票仍待人决策，本次作为其在当前架构下的补充研究，不新增重复的冗余选型票。

1. **任务目标给安全约束让步。** 推荐实机路线不为追赶轨迹或维持进给而放松已定义的碰撞/关节安全约束；允许减速、暂停路径推进或在任务允许范围内改变运动。若无可接受解，进入停止处理。带安全约束松弛的方案仅作隔离研究对照，不作为未经验证的实机救场策略。具体约束类别、数值容差及任务允许偏差由既有可行性/任务票接续，本次不虚构其数值。

2. **关键计算/执行故障停止并锁存。** 求解失败、命令已过有效期、必要几何/导数无效或执行反馈失效时，推荐冻结任务推进并触发独立于正常任务求解的执行端停止路径，不持续复用上一次运动指令、不自动切换未经验证的 CPU/GPU 后端。停止必须通过实际反馈及停止距离验收，发零速不等于已经物理停住。上位机卡死或通信中断时的执行端超时保护也须验收。故障消除、状态/覆盖恢复并人工确认后才恢复，且恢复前重新核对当前状态与路径衔接。

停止动作的具体制动方式、触发时间和执行端能力仍须核验；不在此批准无条件断电或声称静止机器人能够阻止外物继续撞上。已接受的短时丢帧和单源有效覆盖策略保持有效；一次性能预算超期是否使命令失效，取决于后续明确的观测/命令有效期，不将所有统计超期混为同一故障。

以上为待接受的策略提案。用户答复后再讨论预算分配、有效期与验收门；本票保持 open，尚未修改运行逻辑。

## 冗余研究后的修订提案（待用户答复）

[九轴冗余与安全优先级研究](../research/nineaxis-redundancy-safety-priority.md)已完成。该研究细化前文“任务让步”的触发条件，不将原提案记为已接受。正常避障优先在满足约束的解集中保持 5D 工具任务和原进给，利用滑轨与其余关节协调换姿；若原进给不可行，优先保持路径几何/轴向并自动降低或暂缓进给，仍允许整臂自运动。上述正常调节不触发故障锁存。

只有这些调节仍不能兼容任务与约束时，才进入任务冲突处理；自动离轨或退让必须另有预先允许且验证过的任务边界。关键输入无效、求解数值失败、结果过期和执行失效与正常冗余避障分开。停止与人工恢复建议仍待用户决定，不能用机器人冗余代替故障处置，也不能把零速宣称为对移动障碍安全。

联合求解应表达上述优先关系；普通加权目标不自动提供严格优先级，降低进给也不是将最终九轴速度简单同比缩小。具体采用严格任务约束、层级求解或等价实现由优先级需求及对照证据决定，未在此选择新库或启用开关。冗余目标及允许的任务偏离交接既有“选定冗余目标与优先级”，故障/松弛边界交接既有“选定不可行/裕度/降级策略”，保持原票据身份。

## 阶段决议：冗余避障与任务调节优先关系已接受

用户阅读九轴冗余研究推荐后回复“同意推荐”。据此确认以下行为路线，覆盖上文对应的待确认提案：

1. 在满足安全约束与执行器限制的可行解集中，优先利用滑轨和旋转关节协调自运动，争取保持 5D 工具路径、轴向和原进给。
2. 原进给不可兼容时，优先保持路径几何与工具轴向，自动降低或暂缓进给，仍允许整臂自运动。正常冗余避障及进给调节不触发故障锁存。
3. 上述调节仍无法兼容时，暂停工艺任务并进入任务冲突处理；退让、离轨、重规划或停止必须符合另外定义的任务和执行边界。此次没有批准任意自动离轨或自动恢复。
4. 状态/覆盖失效、计算失败、指令过期及执行失效与正常避障分开处理。冗余不能成为忽略故障的理由；停止动作、锁存触发与恢复条件的具体方案仍待后续确认。
5. 延续既定统一控制框架，按效果择优完善冗余协调。普通权重不等于严格层级；具体数学实现、任务容差、松弛边界和是否采用分层求解须验证，不因本次答复启用零空间开关或更换框架。

证据与限制见[九轴冗余研究](../research/nineaxis-redundancy-safety-priority.md)。本次确定行为优先关系，不代表已证明九轴能在任意障碍下保持任务，也未完成数值/动态/实机验证。后续验收须分别覆盖冗余可解、降进给可解、任务冲突和关键故障四类场景。本票仍 open；预算、有效期、故障动作和恢复规则尚未收敛。

## 本轮提案：关键故障停止与恢复（待确认）

本轮只补充关键故障处置；正常冗余换姿和进给调节不锁存，已有覆盖恢复＋人工确认决议不重复投票。

- **故障触发与停止**：当关键状态/几何信息无效、无法获得有效可执行的控制解、候选结果已过有效期或执行反馈失效时，冻结工艺推进，拒绝该候选命令，触发经验证的停止路径并锁存。求解报告不可行、数值故障及超时分别记录，不能统称全局无路。性能统计超期与命令失效区分，允许丢帧的条件继续按既有观测契约。
- **笔记本之外的保护**：上位机卡死/断线必须由执行侧独立监测命令有效期并触发停止；同一台笔记本上的普通 ROS 节点不能作为整机卡死的唯一保护。具体驱动/下位机是否支持、需要补哪层，由硬件契约核验，不声称现有硬件已经具备。停止方式依电机、制动和保持能力验证，不能把发零速或无条件断电视作已经可靠停住。
- **恢复**：推荐把已确认的覆盖故障人工恢复原则扩展到上述关键控制/执行故障。故障原因消除，状态/观测及执行链重新有效，确认停止反馈并重核当前位置和路径衔接后，进入待恢复状态；人工明确恢复才允许任务重新启动。普通节点重启、重新收到数据或清除日志不能自行恢复运动。

该提案不选择具体停止类别、不声称法规符合性，也不授权盲目退让；实际停止路径与持续接近障碍的风险仍须在试验场景与任务边界中验证。任务冲突后的自动恢复/重规划、有效期数值及预算分配尚待后续一轮。本节没有用户接受前保持提案状态，未改代码。

## 本轮提案：任务恢复与预算定案方法（待确认）

### 正常调节自动恢复，任务冲突须确认

推荐在数据和控制持续有效、未进入故障或任务冲突状态、仍处原任务允许误差内时，正常冗余换姿/降进给/暂缓进给可在约束重新允许后自动平滑恢复进给；恢复要有经验证的稳定性与滞回条件，避免障碍边缘反复启停，不能只凭一帧空点。

若已经进入任务冲突（保持原任务连零进给也不可兼容）或需要离开工艺路径，则冻结工艺推进，不自动授权离轨执行。可复用 MoveIt/OMPL 与既定 AEB-RRT* 插件生成候选过渡/绕行路径；候选生成不等于执行授权。推荐校验当前状态、最新环境、路径起点衔接及任务条件后由人工确认执行，执行时仍受实时控制约束。沿用现有 transition_planning_server 的过渡语义，不新建平行编排链。任务冲突若进一步无法取得有效可执行控制解，立即按已定关键故障规则处理，不能在等待人确认期间盲目保持旧命令。故障锁存不得被自动重规划解除。

### 从允许工况推导预算，以目标机测量验收

推荐先界定试验模式的机器人速度/负载、障碍运动边界、有效观测覆盖、允许几何误差及停止能力，再建立一致的反应/制动距离模型，反推观测年龄、控制计算、传输、执行响应和看门狗等时间上限。不同项须有清晰起止时间，避免重复累计或遗漏传感器采样等待与时钟误差；指令有效期不能在转发/重发时重新起算而延长陈旧命令寿命。

既有 50 Hz / 20 ms 与 miss≤1% 仅保留为带适用范围的历史性能基线，不替代完整反应预算或准许超龄指令执行。阈值需在验收前固定来源、工况与通过条件，以本机组合负载下端到端测量及实际制动证据验证，记录分布、尾延迟、观测最大值和超期处理；有限样本最大值不是理论最坏时间保证。达不到则优化、收紧允许速度/工况或拒绝该模式，不为让测试通过随意放宽安全阈值。

具体数值依赖尚未完成的时延/几何/硬件证据，继续由既有对应票接续并在启用模式前定案；本轮只决定上述方法，不凭空指定毫秒或距离。两项提案待用户答复，本票仍 open。

3. **按允许工况推导时间上限，再实测验收。** 根据机器人速度/负载、障碍运动边界、覆盖与几何误差、停止能力建立反应和制动距离模型，分配观测年龄、计算、传输、执行与看门狗预算。明确各时间段起止，计入采样等待和时钟误差，避免重复累计；转发或重发不得延长陈旧命令有效期。
4. **测试不能反向放宽安全要求。** 50 Hz / 20 ms 等历史指标仅作性能基线。验收前固定工况、阈值来源和通过条件，在目标笔记本组合负载下测量端到端时延、超期行为及实际制动；不达标则优化、降低允许速度/收紧工况或拒绝启用该模式。有限样本最大值不作为理论最坏时间保证。

### 实机任务不能购买安全约束违反量

推荐实机运行模式不允许为保持进给、跟踪精度或取得一个数值解而放松已定义的自碰撞、环境碰撞及关节/执行器安全约束。任务按已接受的冗余协调、降低/暂缓进给和任务冲突规则让步，任务误差仍受已定义的任务边界限制。增加安全违反惩罚权重不等于禁止违反。

这里区分三件事：任务允许误差、安全约束松弛变量、求解器数值容差。数值容差须预先定义、按量纲核验并计入误差/裕度预算，不能被当成额外可消费的安全违反额度。碰撞裕度按已接受的工况与几何/制动证据定案，不在本轮凭空选值。带安全松弛的旧实现可保留用于隔离回放或仿真对照，其输出不进入实机命令链；不得在故障时自动启用该模式。没有有效可执行解时沿用已定故障处理，不能宣称取消松弛即可保证任意动态场景安全。

本轮决定适用原则；具体 QP 汇编、约束分类、数值容差及裕度证据交接原“选定不可行/裕度/降级策略”，不将该原票直接记为完成，也不因此重写或替换 CBFpy/qpax/JAX。

### 验收对象贯穿求解结果、下发命令与实际反馈

推荐将 QP 后滤波、积分、限幅、速度到位置转换、通信和驱动响应纳入同一控制契约。优先把可表达的速度/加速度/变化率限制及平滑要求纳入求解；必须保留的后处理须验证对约束的影响，并在命令有效期内检查最终下发候选，而非只检查 QP 原始输出。最终检查失败或超时不能发送未经验证的候选，按已定停止路径处理。
