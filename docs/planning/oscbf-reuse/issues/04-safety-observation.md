## Question

即时环境几何如何覆盖静态、未确认、动态障碍，以及固定工装、地面和盲区？选择点云最近邻、上游距离场或组合时，如何定义可观测范围、置信状态、点密度/体素误差、非光滑梯度与约束槽截断？

建议分类与跟踪只增强速度估计，不能决定障碍是否存在；任一新障碍无需等待静态确认或轨迹关联。契约至少讨论采集时间、frame、有效期、距离/法向与其对应的机器人几何、误差界、覆盖/无观测状态、跨传感器冲突、槽位不足。明确已知工装静态模型与在线观测职责。

本票定接口与表示，不实现一个新的全能感知框架。

## 事实与待选方案

[重梳说明](../REBASE.md)记录了静态障碍进入距离场、当前控制入口只消费 tracks 的代码证据；这是待验证的覆盖缺口。给 tracks 增加时间戳不能独自解决表示切换导致的障碍遗漏。

| 候选 | 复用方式 | 代价与决策条件 |
|---|---|---|
| 直接点云距离查询 | 官方驱动、TF2、自体过滤和 PCL，项目只接观测契约 | 需定义稀疏/遮挡误差、几何包络与梯度切换；最近采样点不是保守净空保证 |
| 上游距离场 | 适用发行版的距离场库，项目接距离/法向与有效性 | 需核算力、内存、地图刷新时延及未知空间语义 |
| 组合表示 | 已知固定几何加即时在线观测，跟踪补充速度 | 必须解决冲突、重复约束与时间一致性，不能无边界堆叠两套地图 |

推荐先保证障碍观测连续覆盖，分类与跟踪仅提供增强信息；上游维护边界现已确认，本票成为下一轮前沿；最终表示仍待与用户讨论。

## 访谈第一轮：观测职责与运行边界（2026-09-07，已回答）

本票由 Codex 在本地记录推进，远端未领取；保持 open。本轮先确定职责与可接受行为，后续再讨论具体距离后端、字段、过滤接入及误差预算，避免在前提未定时选择包。

### Q1 障碍存在是否独立于跟踪成功

建议：有效的新障碍观测不等待对象 ID、分类或稳定速度估计就进入避障输入。跟踪只增强运动估计；关联失败不能删除仍可观测的几何障碍。速度未知时明确标记未知，依据后续验证的运动边界处理，不能当作零速度。

取舍：可降低跟踪等待造成的遗漏，但需要处理噪点和未知运动带来的保守反应。有效性筛选仍存在，不代表每个原始噪点都直接成为约束。

### Q2 固定工装与在线观测是否采用分工

建议：已知工作台、夹具、地面以经校验的固定几何作为约束来源，在线观测补充人员、物体及环境变化；共享坐标、标定依据和几何来源记录。在线空帧不清除固定模型，发现模型与观测冲突时不能由固定模型屏蔽新障碍。

取舍：减少已知环境对持续可见性的依赖，但要承担场景几何测量与变更后的重新校验。该建议触及 ADR 0003 的“感知是唯一障碍数据源”措辞：若接受，后续 ADR 必须显式补充固定几何来源，继续保留其输入失败策略，不静默覆盖原决议。

### Q3 无法证明必要空间覆盖时是否停止并锁存

建议：与当前动作及停车所需空间相关的覆盖缺失、观测过期或容量溢出，若没有仍有效的保守表示，则停止并锁存，待覆盖恢复且人工确认后恢复。已经定义的单帧异常丢弃策略保留；只允许在已有有效观测及其适用域内继续，不能把所有未知空间当作空闲。

取舍：遮挡或杂乱环境下可能增加停机。若要求持续运行，需要另行明确受限动作及其有效覆盖证据；不能仅以降速代替该证据。相关空间范围、有效期及数值仍待后续本票与时间模型/验证票联动确定。

### 后续轮次（前置未定，暂不请求定案）

依据本轮回答选择距离表示与复用后端，细化自体过滤、采集/状态时间、覆盖及未知状态、跨传感器冲突、误差预算和槽位溢出的契约。依赖事实已有研究链接；构建和目标机测量不足处单独标明验证门，不请求用户猜测 API 或性能。

## 访谈第二轮：距离后端的首条实施路线（已回答）

在已接受“固定几何＋在线观测”的前提下，是否先以 CPU 上的成熟点云/几何库建立在线距离查询基线，将 GPU 距离场保留为经对照验证后采用的候选？

推荐先采用 CPU/PCL 路线形成可验证基线，复用空间索引与点云处理，项目仅负责机器人几何对应、观测有效性和控制适配。这里的点集距离必须受采样/遮挡/机器人包络误差和有效域约束，不能直接宣称是真实净空下界；无法建立适用域时按已确认覆盖失效策略处理。与固定工装模型的距离使用成熟几何查询实现。

替代路线是现在就把 GPU 距离场作为首条必需路线：可能利用 GPU 加速稠密表示，但前置增加具体发行版构建、6 GiB 显存适配、地图动态清除/未知语义和端到端延迟验证。已有研究列 nvblox 为候选，本机可见 GPU 并不证明这些门已通过。

此选择决定首条距离观测路线，不决定控制求解使用 CPU 还是 GPU；后者属于控制接入和验证票，并以目标机实测为依据。用户回答后再细化自体过滤接入、跨传感器冲突和接口字段，不以此次回答一次性批准所有技术细节。

## 阶段决议：第二轮已确认，整票仍 open

用户对“先采用 CPU/PCL 建立距离查询基线，GPU 距离场通过验证后再接入”的建议回复“接受”。确定 CPU/PCL 为首条在线距离查询基线路线，复用点云处理与空间索引；固定模型结合成熟几何查询实现。GPU 距离场保留为兼容性、显存、动态更新及端到端对照通过后可接入的候选，不是当前必需依赖。

此决定不选择控制求解的 CPU/GPU 后端，也不证明采样点距离是实际净空下界。采用版本、几何误差/有效域及目标机性能仍需验证。既有部署和覆盖失效决议继续有效。

## 观测接口草案（工程展开，尚未定案）

| 信息 | 拟定契约 |
|---|---|
| 来源与追溯 | 传感器/固定模型来源、序号或模型版本、标定记录标识；保留冲突信息 |
| 时间与坐标 | 采集时间或扫描起止时间、时钟域、所用机器人状态/TF 时间；变换到既有 base_link；禁止以回调到达时间替代采集时间 |

| 误差与适用域 | 采样/体素、自体过滤、机器人包络及标定误差依据；只有界已成立的有效域才允许据此构造保守距离，否则为未知 |

## 访谈第三轮：传感器冲突与贴近本体观测（待回答）

### Q1 单传感器故障或双传感器冲突

建议采用证据决定是否继续：一方报告有效近障碍、另一方未看到时保留近障碍，不平均消除；一方失效时只有另一方仍能独立满足当前动作和停车所需空间的覆盖及有效性要求，才允许继续。不能证明覆盖则按已定策略停车锁存。不是“总是必须两台在线”，也不是“任一在线即可继续”。

取舍：与双设备强制在线相比可减少非必要停机，但必须验证单设备覆盖；与任一在线即可相比会更保守。若用户要求首版两台都健康才允许运动，则采用更简单的联锁作为运行约束。

### Q2 自体过滤中无法区分本体与近身外物

建议：优先复用上游自体过滤能力，并以“贴近机器人表面的外物仍能保留”为验收门。无法确定的点不直接当作本体删除，保留为潜在障碍或标为该区域覆盖未知，依既定规则处理。不能为减少误停无依据扩大机器人剔除包络。

取舍：可能增加近身误报/停机；相反若扩大剔除区则会增大对真实外物的漏检范围。具体上游接入由已有 Humble 兼容研究和构建/回放验证决定，用户不需要猜测 API。

用户明确希望两个传感器“配合合作”，并调用 research 要求对冲突处理和自体过滤给出研究推荐。这是协作目标的澄清，不是对第三轮 Q1/Q2 的接受答复。第三轮保持待决。

### 与现状的差距（本地静态核对）

- `config/perception_dual_sensor_real.yaml:34` 的 LiDAR 输入为空，当前配置不能直接当作双传感器已启用的证据。
- `portable_oscbf/work/fusion_engine.py:240` 使用参与帧的最大时间作为融合时间，后续合并降采样的点集不保留逐源采样时间。下一步接口必须避免以最新帧时间把另一源旧点重新标为新鲜。

上述为源码静态核对，未运行传感器或重放测试。源文件后续变动时应重新定位，不能把实现差距当作已经修复。

### 研究结果与第三轮修订推荐（研究完成，决策仍待用户）

研究资产：[Mid-360S 与 Gemini 335L 协作、冲突处理和自体过滤研究](../research/dual-sensor-cooperation.md)。报告核验了厂商规格、时间同步接口和上游过滤源码；不代表构建或设备验收通过。

Q1 修订推荐为“正常双源持续互补＋统一的带来源/时效/覆盖观测”：各源独立及时更新，重叠区交叉核验并对一致观测去重，各自视场补充覆盖；有界时间关联不阻塞所有新观测。不同有效几何先保留冲突，不能平均抵消近障碍；故障降级仅在已验证的剩余覆盖内成立。

Q2 修订推荐为“共享机器人几何、按源时刻和视点先过滤再融合”：仅删除可信本体点，保留不确定边界或标为覆盖未知；一个视点的阴影不能自动否决另一视点的观测。复用上游几何分类，薄适配显式检查 TF/时间和有效性。避碰包络与点云剔除范围分开维护，不能用增大剔除 padding 掩盖标定/时间错误。

具体过滤包暂不批准：MoveIt Humble ShapeMask 没有 SHADOW/UNKNOWN；robot_self_filter 有 SHADOW 但存在 TF 失败回退和 Humble 构建验证门。详见研究证据，后续据功能需要及验证选择上游入口。用户尚未对这两项修订推荐作接受答复。

## 阶段决议：第三轮修订推荐已接受

用户同时要求研究 CPU/GPU 启用与分工。该研究不撤销已接受的 CPU/PCL 感知距离基线，也不代表批准安装 GPU 依赖或切换生产控制后端。

### 待决取舍：首版是否优先复用 MoveIt Humble 的几何包含过滤

推荐首版优先接入 MoveIt Humble 的 ShapeMask 几何包含能力，按每个传感器的消息时刻取得机器人形状变换，复用现有 URDF/TF；项目适配层负责时间/标定有效性、分类原因与覆盖未知。规划侧可用按源配置的 PointCloudOctomapUpdater，控制观测侧直接使用过滤结果和有效性数据，不把规划地图更新作为高频控制输入的前置门。

取舍：该路径承接已有 Humble/MoveIt 技术栈，但 ShapeMask 不提供阴影分类，不能声称它判断了机器人后方空间的可见性。首版把未获证据的遮挡区域保留为未知，通过双源覆盖和既定失效规则处理。若需要改善阴影点识别以减少误报，再验证 robot_self_filter 的射线分类；其 Humble 构建与 TF 失败处理需要补丁/适配验证。现有研究见[双源协作与过滤核验](../research/dual-sensor-cooperation.md)。

另一条路线是首版就接入 robot_self_filter 的射线分类，承担额外的兼容和失效语义适配。是否首版就需要这项能力，是现在需要用户确定的范围取舍；不是要求用户判断源码 API。

### 推荐一并交接的接口边界

这是对已接受行为的工程展开，不另改变其含义：

- **感知层拥有观测**：各源点集/几何、原始采集时间、所用变换/机器人状态时间、来源及标定版本、覆盖与失效原因。固定环境模型独立保留版本和校验状态。
- **CPU/PCL 查询适配拥有几何对应**：输出关联的机器人包络/连杆、最近几何对、测得距离及方向有效性，不暴露原始无身份浮点槽作为唯一契约。复用现有经核对的机器人几何作为基线，未来是否替换由控制接入票与原几何核对票决定。
- **控制适配拥有约束解释**：把测得距离、数据龄、运动边界和已验证误差转换成控制约束；不能对离散索引盲目求导，不能把点集距离直接命名为安全距离。接入票明确几何点/法向与机器人 Jacobian 的对应及切换行为。
- **有效域必须先成立**：只有采样、标定、机器人几何与时序误差在适用域内有依据，才允许使用相应距离约束。若无法得到所需几何误差界，按既定覆盖失效规则处理；这不是允许未验证的默认裕度上线。
- **容量是契约的一部分**：查询候选筛选必须保持所需障碍覆盖；无法证明保留覆盖时报告溢出/无效，不沿用按点数选前八团块的静默截断。具体固定容量和约束精简方法交由控制接入/几何验证票以证据确定。

## Resolution comment（待发布）

用户在理解基础本体过滤与阴影过滤区别后回复“接受这个”，确认首版先复用 MoveIt Humble 的机器人几何包含过滤，双源分别处理后融合；阴影射线过滤仅在后续实测发现明确需要时再评估。结合此前逐轮答复，本票的规划决议现完整记录如下。

1. **障碍来源与连续性**：固定环境模型与在线双源观测共同提供几何；有效新障碍不等待跟踪成功，分类/关联变化不使仍有效的障碍消失。未知速度不作零速度。
2. **正常双源协作**：两源独立及时更新，保留采集时间、来源、标定依据、覆盖及冲突；重叠观测核验去重，一方未看到不否决另一方有效障碍，冲突不简单平均抵消。
3. **首版过滤与距离路线**：各源按采样时刻机器人姿态复用 MoveIt Humble ShapeMask 几何包含能力，适配层显式检验有效性；只剔除可信本体点。边界不确定点保留或标为未知。CPU/PCL 负责点云处理与查询基线，阴影过滤和 GPU 距离场不作为首版必需项。
4. **控制接口交接**：按本票“观测接口草案”和“推荐一并交接的接口边界”落实语义：感知提供带时间/来源/覆盖的观测；查询提供机器人对应几何与测得距离/方向；控制适配结合经验证的误差与运动边界构造约束。具体消息编码属于实现，几何包络替换与 Jacobian 对应属于控制接入决策；不把采样点距离直接当作保守净空。
5. **失效行为**：容量不足、过期、冲突或遮挡使必要覆盖无法成立且无有效保守替代时，停车锁存；剩余单源只有在已验证覆盖内可继续。覆盖恢复加人工确认后恢复，短暂异常仍受已有有效观测及适用域约束。
6. **验证责任**：沿用收敛轮责任表及原票接续，落实上游版本/构建、贴近本体障碍保留、TF 失败、时序/误差界、容量覆盖和目标机全链路验证。未通过验证不得接入运行；若证据否定过滤/距离路线，显式重开相应决议。尚无数值依据的阈值保持待验证，不以本票关闭代替验收。
