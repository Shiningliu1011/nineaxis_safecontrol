## Question

先替换哪一段、用什么对比结果进入下一段、失败如何回退？怎样把旧 tracker 中自体过滤、tracks 契约、标定工具移植等实施票改写为复用任务，而非继续增加自研？

候选顺序：锁定依赖与回放基线→官方驱动/TF/过滤的独立输出→即时几何适配进入现有控制链做对照→上游内核与九轴适配等价验证→完整执行链验证→旧模块退役。顺序需依兼容研究结果定案；不得在接口未定时把它当可直接执行的清单。

每个迁移段说明可逆入口、比较数据、验收门、替换/保留模块、owner、依赖版本及许可证记录位置。实现票留在普通 backlog。

## 候选路径与取舍

迁移须遵守用户补充的[效果择优原则](03-reuse-boundary.md#用户补充决议按实际效果择优保留待发布)：已有实现可凭比较优势保留，验证可用不等于必须替换。[自碰撞保留现有 OBB](05-control-adoption.md#阶段决议自碰撞保留现有-obb)是已定边界，不列入球模型替换或整体删除目标。

渐进替换易于归因和回退，但会短期保留两条比较路径；整体替换减少临时接线，却把感知、控制与执行故障混在一起。推荐渐进替换，并在每一阶段明确哪一条拥有命令发布权，比较路径仅记录结果。

## 决策后可能改动的位置

- `package.xml`、`setup.py`、相关 launch 与配置：固定依赖并设置可回退的接入入口。
- [原票据接续](../REBASE.md)：重写已有自体过滤、tracks、感知健康和标定工具实施票，保留来源与既有验收要求。
- `portable_oscbf/work/`、`portable_oscbf/vendor/`、对应测试和部署文档：在替代验证通过后逐项判定退役；独立验证基线单独说明保留原因。

## 本轮提案：分段接入、验收后切换、最后退役（待确认）

本票已本地领取，未远端领取。以下依据已接受的维护边界、观测契约、控制接入及验证决议提出，不重新选择 OBB 或 CPU/GPU 生产后端。

### 推荐迁移顺序

| 阶段 | 复用与改动范围 | 进入下一阶段的依据 |
|---|---|---|
| 保存可复现基线，明确执行门 | 记录当前代码及未提交改动快照、依赖/补丁、配置、模型和回放输入；核查现有硬件反馈、停止及独立超时能力缺口 | 能复现现状；对照指标、失败场景和版本来源明确。基线仅代表现状，不自动取得实机准入 |
| 双传感器观测独立对照 | 优先复用官方驱动、现有 TF/标定权威、MoveIt 基础本体过滤和 PCL；补足逐源时间、来源、覆盖和有效性适配 | 双源互补、错误时间/TF、遮挡、空帧和单源故障符合观测契约；候选仅记录输出 |
| 环境距离接入回放控制链 | 验证局部占据体素＋FCL 与全臂 OBB，补几何查询到九轴导数的适配；先接现有统一求解入口做离线对照 | 包围关系、距离/导数、动态响应、容量和未知覆盖符合约定；不等待分类跟踪，不静默截断 |
| 控制模块逐项择优 | 保留九轴、5D、OBB 与硬件适配基线，按具体缺口复用 OSCBF/CBFpy 等模块或最小补丁；运动学替代及 CPU/GPU 按既定路线分别对照 | 同一输入/精度口径下任务、约束、故障与端到端性能满足要求，并有实际收益；无收益的替代不必推进 |
| 完整执行链准入与受控切换 | 验证后处理、命令有效期、实际反馈、停止/恢复与执行侧独立看门狗；前置条件满足后才进入受控低速实机验证 | 适用工况和阈值定案，动态回放与相应故障注入通过，实机准入条件满足；扩大速度/负载须追加该工况证据 |
| 逐项退役 | 清理已证明可替代的旧运行入口、依赖、配置和重复实现；保留必要回放数据及独立验证基线 | 替代与回退证据完整，调用方完成迁移，无旧入口残留依赖，运行文档同步 |

这些是接入和准入的顺序，不要求停止独立准备工作。硬件停止能力缺口从第一阶段开始核查和补齐，不能等最后才发现；任一实机运动前必须满足相应执行安全前置。依赖兼容若阻塞几何适配，可先做必要的最小兼容修补，但不捆绑无关内核替换，仍分开记录效果与归因。

### 切换与回退规则

每段先用冻结输入离线对照；若后续使用在线旁路比较，候选不持有命令发布权，其资源开销也须计入目标机组合负载。实机运行始终只有一个正式命令发布者，不允许运动中自动在新旧控制链或 CPU/GPU 后端之间切换。

候选不达标则保留合格现有实现，修正候选后重新验证。已运行模式发生关键故障时先沿用停止锁存规则；软件回退在确认停止后进行，成套恢复已记录且兼容的代码、依赖、配置、模型和接口版本，检查当前状态/路径并按恢复规则重新启动。旧版本若也不满足当前工况的观测或执行契约，只能作为离线基线，不能以“回退”为由恢复不合格实机运动。

### 退役与原任务接续规则

推荐仅在正确性、覆盖、任务、故障与目标机性能验收通过，且确有收益、下游无旧接口依赖、回退可复现后，逐项删除旧运行实现。删除在后续可审查的实施变更中完成，本次不授权立即删代码。基线代码可保存在可复现版本中；确有独立验证价值的测试实现可以保留，但与正式运行入口隔离并说明维护责任。现有自碰撞 OBB 和项目独有能力继续按已接受边界保留。

实施交接沿用[原票据接续](../REBASE.md)：自体过滤改成上游过滤接入与边界验证；tracks 相关工作补足连续几何契约且保留运动估计职责；健康状态接入逐源有效性与故障规则；标定工具遵守既有外参权威；控制、时延、几何与硬件工作接续验收决议。不另建同义实施票，不把有未完成证据的原票自动关闭。每段实施启动前填写上方交接模板中的负责人、固定版本、验收门和回退记录。

本轮请求确认两项取舍：上述分段迁移与受控切换顺序；满足替代收益、验收和回退条件后再逐项退役。尚未收到答复，整票保持 open，未实施迁移或删除代码。
