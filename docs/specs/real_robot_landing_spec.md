# 规格：真机落地（Hardware Landing）

状态：draft（issue tracker 未配置，尚未发布）
来源：2026-08-22 grilling 共识（14 项决策）+《docs/real_robot_execution_plan.md》
领域词汇遵循 `CONTEXT.md` 词汇表；ADR `0001`（过渡管线以 transition_planning_server
为唯一语义）对本文档生效。

## Problem Statement

项目目前在 MuJoCo 仿真里已经全自动跑通"随机位姿 → 过渡管线 → OSCBF 跟踪蝴蝶轨迹"，
但其执行端是模拟执行器（带 jerk 限幅的位置跟随仿真）。真实九轴机械臂（ninezzhou：
DrEmpower 模组，J1 为棱柱关节）全部装配在手上，却完全没有软件驱动通道：没有 CAN
驱动、没有真实编码器反馈进入状态流、没有任何真实电机运动命令的发送器。机器人处于
"仿真闭环 + 真实硬件沉默"状态。任何直接尝试给真机发命令的行为都缺少安全边界：
没有反馈超时/看门狗、没有限幅校验、没有故障锁存/恢复语义，也没有 J1 传动标定前
的 fail-closed 保护。

## Solution

新建一个真机执行端：命令流（100 Hz 位置命令）经安全网关（限幅、超时、故障码、
急停语义、锁存与人工恢复）后，通过 CAN（DrEmpower 位置模式 0x19 帧）驱动电机；
电机反馈帧经解码、单位换算、零位偏移后作为状态流返回——与现有闭环完全同构，
替换模拟执行端的角色（off 时仿真回归不破坏）。分阶段推进（vcan 验证 → 单关节
台架 → 全臂 shadow → 低速闭环 → 虚拟障碍物 → 实机软障碍物避障），每阶段有独立
验收门。感知侧新建解析障碍物管线（Orbbec Gemini 335L 点云 → 聚类 → 球/圆柱 →
控制器 obs_*），不把稠密点云直接塞进 CBF。

## User Stories

1. 作为现场实验员，我想要真机编码器位置/速度以正确的单位与零位进入状态流
   （`/mujoco_joint_states`），以便 RViz、MoveIt 规划监视与控制内核看到的是
   真实机器人状态，而不是仿真状态。
2. 作为现场实验员，我想要控制器与过渡回放发的 100 Hz 位置命令真的到达九轴电机，
   以便仿真验证过的蝴蝶轨迹跟踪在真机上生效。
3. 作为现场实验员，我想要反馈超时、命令超时、驱动故障、限幅违例时电机立即回到
   零速保持并锁存停车原因，以便故障不会静默发展成失控运动。
4. 作为现场实验员，我想要锁存的停车原因只能由外部健康确认后人工清除，以便恢复
   流程可审计、可演练。
5. 作为现场实验员，我想要 J1 在丝杆传动参数实测前被安全网关强制拒绝运动命令
   （fail-closed），以便避免用错误的 m/s/N 限幅驱动升降轴。
6. 作为现场实验员，我想要 `shadow` 模式（只记录命令与状态、不发送任何 CAN 帧）
   与 `live` 模式一键切换，以便先在记录态验证命令语义再上真机。
7. 作为集成开发者，我想要先在没有 CAN 硬件的 vcan0 虚拟总线上验证帧编解码、
   9 节点轮询时序、丢帧与错误注入、看门狗与重连，以便把驱动层的 bug 在无硬件
   风险的环境中排除。
8. 作为现场实验员，我想要单关节台架流程（只使能一个轴、低转速、正方向与零位
   逐关节确认），以便首次连接真机时风险最小。
9. 作为现场实验员，我想要 9 路反馈轮询延迟与丢帧率被量化（目标 <5ms / <0.1%），
   以便判断 CAN 链路与 1Mbps 负荷是否支撑 100 Hz 控制。
10. 作为现场实验员，我想要低速（仿真速度 10%）下完整跑通过渡管线与跟踪，以便
    在无动态障碍物的条件下先证明全链路正确性（末端误差 <2mm）。
11. 作为现场实验员，我想要实机反馈 + 程序生成障碍物的虚拟避障阶段，以便隔离
    "控制避障好不好"与"感知准不准"两个问题。
12. 作为现场实验员，我想要 Orbbec 点云经背景/机械臂过滤、聚类后输出解析障碍物
    （球/圆柱参数）进入控制器 obs_*，以便 CBF 用可验证的几何障碍模型避障。
13. 作为现场实验员，我想要相机到 base_link 的静态外参由实测值生成 TF 并替换占位
    配置，以便障碍物坐标系不再"猜"而是可验收。
14. 作为评审者/验收者，我想要每个阶段的验收证据（日志、延迟/丢帧统计、跟踪误差
    曲线、避障记录、急停演练记录）可归档可复查，以便证明"真机落地"不是口头宣称。
15. 作为实验员，我想要一套实机 runbook（上电前检查、急停试验、只读反馈、单轴低速、
    九轴低速、传感器、故障恢复），以便每次上电操作都有停止条件与回滚步骤。
16. 作为集成开发者，我想要仿真模式（模拟执行端）行为完全不受影响、一条 launch
    参数切换 sim/shadow/live，以便开发与演示回归成本为零。
17. 作为集成开发者，我想要安全网关、帧编解码、单位换算都是纯逻辑模块（无 ROS、
    无 I/O 依赖），以便它们像现有过渡相位机一样可快速单测。
18. 作为实验员，我想要桥接节点发布遥测（每轴命令/反馈延迟、丢帧计数、停车原因、
    watchdog 状态）以便现场诊断不用翻总线上位机。
19. 作为维护者，我想要仓库内死配置（fcl_todo、real_model_todo、悬空 launch）与
    过时文档计数被清理，以便后来者看到的文档与代码一致。
20. 作为实验员，我想要每个电机当前的 node_id / 波特率通过读取属性（如
    can_node_id）确认而不是假设，以便 9 个关节的通信地址明确无冲突。
21. 作为验收者，我想要"机械零位标记法"零位标定的产物（各轴偏移、正方向符号）落盘
    在显式配置文件里，以便零位漂移或换电机后可以重标定而不改代码。
22. 作为实验员，我想要首次实机避障实验使用单个软质泡沫球/柱、低速运行、隔离区
    内执行，以便任何异常都在可控范围内。

## Implementation Decisions

### D1 执行端唯一新节点：真机执行端（hardware_bridge）

- 角色与模拟执行端同构：订阅命令流（`/oscbf_command`，JointState.position，100 Hz）
  → 安全网关 → 单位换算 → DrEmpower CAN 帧 → 电机；电机反馈帧 → 解码 → 单位换算
  → 发布状态流（`/mujoco_joint_states`，BEST_EFFORT、深度 20，遵守 ros_conventions）。
- `hardware_mode` 参数：`sim`（不参与，模拟执行端照旧）/ `shadow`（记录命令与状态、
  无发送 API，照搬参考项目影子网关语义）/ `live`（发送 CAN）。
- **不触碰**过渡管线语义（ADR 0001：transition_planning_server 权威）：过渡回放仍
  走命令流下发，watchdog 从回放开始全程生效。MoveIt 仅用于规划与 PlanningScene
  碰撞检查；controller_manager/ros2_control 不进入真机路线。

### D2 安全网关（位置契约）

- 移植并改为位置契约（参考项目 newaxis 的 VelocityCommand 契约改写）：
  - 反馈结构：位置、速度、时间戳、反馈健康、急停状态、驱动错误码。
  - 命令结构：目标位置、时间戳、失效时间、来源、停车原因。
  - 看门狗配置：反馈超时、命令超时、每轴速度上限、相邻命令变化上限。
- 规则：超时/急停/错误码/关节数不匹配/非有限值/限幅违例 → 输出"零速保持"命令
  （当前目标位置 + 零速度），锁存首个停车原因，直到外部监控健康确认后人工清除；
  锁存期间持续输出零速。**网关只检验、不重塑**（限幅违例是停车事件，不是裁剪）。
- `require_hardware_executable`：J1 传动未标定时任何 J1 运动命令在编译/初始化层
  fail-closed；标定数据注入后才放行。
- 软件零速 ≠ 物理停止：物理急停（断电/制动）为独立链路，制动距离需在 H4 阶段实测
  并与 CBF 裕度对比。真机模式下命令目标为零速保持帧（0x19 位置模式以速度字段为零
  的当前目标位置实现保持）。

### D3 通信层

- 帧编解码为纯函数模块（无 I/O）：DrEmpower 0x19 位置命令（目标角 deg、速度、
  滤波/加速度字段）、0x08 系统命令（clear_error/set_zero/estop/sync_start）、
  反馈帧解码（位置 deg、速度、转矩、状态位）、使能/失能序列
  （clear_error → closed-loop(IDLE=1 逆过程)）。字段单位以厂商库为准（0x19 速度
  字段单位为待确认项，锁定后不再变动）。
- socketcan 后端（python-can socketcan 接口）：接口名参数化（vcan0/can0）、
  9 节点轮询、丢帧统计、时间戳、重连、错误码上报；无 ROS 依赖，可注入测试替身。
- 适配器：CANable 2.0（candleLight/candleusb 固件，内核 gs_usb 驱动）；波特率
  1Mbps，终端电阻双端确认。

### D4 单位与零位

- 关节↔node_id 映射（推荐 J1–J9 = 1–9，实读确认）、rad↔deg 换算、零位偏移
  （`q_urdf = 反馈读数 × 比例 + 零位偏移`）；J1 的 deg↔m 换算依赖丝杆传动参数。
- 零位标定走"机械零位标记法"：手动摆机械零位 → set_zero 固化 → ±5° 命令验证
  正方向与符号，偏移表与方向符号存配置文件，可重标定。

### D5 感知管线

- 新增解析障碍物提取器：订阅 PointCloud2（Gemini 335L，官方 orbbec_camera 驱动）
  → 背景/机械臂自过滤 → 聚类 → 球/圆柱参数 → 控制器 `obs_*`（M9 接口路径启用，
  `sdf_*` 不启用）。
- 外参：实测值生成静态 TF，替换占位 `camera_to_world_static`/`use_tf:false`；
  外参参数化存储，验收流程为已知尺寸物体验证（点云位置误差 <20mm）。
- 第一版实验条件：单个软质泡沫球/柱、低速、隔离区；点云失效/老化按时间超时平滑
  降级为停车，不误判。

### D6 频控与集成

- 控制频率保持 100 Hz（与仿真一致）；过渡回放速率按真机平滑性允许放宽到电机内置
  插补可承受水平（详估不计入 AC）。
- 桥接节点遥测：每轴命令/反馈延迟、丢帧计数、停车原因、watchdog 状态，文本日志
  + 遥测字段并存，便于现场诊断与证据归档。
- launch 增加模式分支与感知开关；默认行为（模拟执行端 + 弹窗演示）保持不变。

### D7 文档与工程化

- 新词入库`CONTEXT.md`：真机执行端、安全网关、解析障碍物、（可选）零位标定表。
- 清死配置（fcl_todo、real_model_todo、引用不存在文件的 launch）与过时文档计数；
  pytest 全量入口脚本；验收证据归档策略在 H0 落地。
- 实机 runbook（docs/real_robot_runbook.md）：上电前检查、急停试验、只读反馈、
  单轴低速、九轴低速、传感器、故障恢复，每步含停止条件与回滚。

## Testing Decisions

- **好测试的定义**：只测外部行为（话题进/话题出、命令帧进/状态帧出），不测实现
  细节（内部循环变量、内部存储不测）。
- **主缝隙（跨模块边界，唯一）**：真机执行端节点的话题级行为。先例：
  `tests/test_oscbf_plant_smoke.py`、`tests/test_oscbf_controller_smoke.py`
  （in-process rclpy）。注入 FakeCANBackend（模拟反馈帧/丢帧/错码/超时/故障码），
  断言：状态流输出正确（单位/零位）、停车事件与锁存恢复符合网关语义、J1
  fail-closed、shadow 模式无发送调用。全链路回归保持现有
  `tests/test_oscbf_full_flow_e2e.py`（sim）并新增 shadow 模式下同输入命令记录对照。
- **纯函数子缝**（先例：`tests/test_transition_executor.py` 与 portable 内核测试）：
  帧编解码 round-trip + 厂家样例帧对照；安全网关参数化测试（各触发原因、锁存、
  人工恢复）；单位换算（rad↔deg、零位偏移、J1 未标定断言）。
- **vcan0 集成验证**：独立脚本/显式运行（需要 root 与 vcan 内核模块），作为 H1
  阶段验收门，不占日常 pytest。
- **感知**：解析障碍物提取器用合成点云单测（聚类 → 球/圆柱参数）；外参验收为
  物理流程（已知物体验证）非自动测试。
- 各阶段验收门指标（阶段计划《docs/real_robot_execution_plan.md》H1–H7）：帧编解码
  100%、vcan 轮询 <5ms、单关节 ±0.1°/1mm 内跟踪、9 路 <5ms/0.1% 丢帧、低速全链
  末端误差 <2mm、避障 dyn_min>0/qp_fail=0、外参 <20mm、无碰撞/可急停。

## Out of Scope

- `sdf_*` 稠密点云/ESDF 路径（只有接口测试，未验证；后续独立规格或另行评估）。
- 力矩级控制与动力学标定（反射惯量、电流-热限制标定不在本规格；用户现场按需
  另起工作）。
- ros2_control 硬件接口插件（真机路线明确绕过；若未来要标准化控制器管理另立项）。
- 可操作度零空间（M8）保持默认关闭（`use_nullspace_policy=false`），本规格不启用。
- 仿真侧 M12 残留偏差的修复（OBB 逐连杆量化、奇异区验证、JIT 预热 <30s）：H0 只
  做欠账清理与登记，不算规格修复目标。
- J1 丝杆传动参数的实测本身（现场事项，软件侧只实现 fail-closed 与参数注入接口）。
- CI/远程仓发布（本地自洽档）。
- 参考项目 robot_oscbf/newaxis 其余外围（HRI 安全栅格、回放审计、RViz 套装）：不
  移植，仅借鉴设计。

## Further Notes

- 前置清单（用户侧）：P1 获取 DrEmpower 厂商包（本机无，帧字段单位待锁定）；P2 J1
  丝杆传动实测；P3 采购 CANable 2.0；P4 急停/制动链路确认与试验；P5 node_id/波特率
  确认；P6 相机固定安装与手动测外参。P1 卡 H1 后半，P2/P4 卡 J1/运动阶段。
- 规格与《docs/real_robot_execution_plan.md》的差别：规格回答"做什么、验收什么"；
  执行计划回答"阶段怎么排、每阶段怎么验收"（H0–H7）。
- 参考项目 `robot_oscbf/newaxis/hardware_contract.py` 与
  `docs/real_robot_hardware_contract.md` 是设计来源，均标注"仅影子模式"——本规格
  把其语义升级为可执行执行端，但保留"未经 vcan/单关节验证不得 live"的监管规则。
- 风险：VMware USB 透传无硬件 CAN 时间戳；0x19 字段单位待厂商库；CANable 在
  1Mbps+9 节点下的实载（H3 实测，超压则调整轮询或反馈广播）。
