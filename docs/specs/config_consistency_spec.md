# 配置一致性规格说明书：生产入口、启动快照与消费契约

日期：2026-09-11。正式票据：[issue #12](https://github.com/Shiningliu1011/nineaxis_safecontrol/issues/12)，Part of #1；Queue：implementation-backlog；Triage：ready-for-agent。

依据：配置一致性交接中“对齐完成与实施交接”及此前八项已确认选择；后期确认优先于早期研究建议。本规格完成规划和发布，不代表产品实现或验收完成。

## Problem Statement

部署人员无法从现有配置确定安全控制器最终使用的值、来源和生效时机。生产 YAML、节点默认值、离线控制内核默认值与遗留字段混在一起，部分字段没有消费方；启动参数覆盖后缺乏可追溯记录，运行时修改又可能部分生效。配置文件遗漏或路径错误可能被默认值掩盖，导致运行与操作者预期不一致。

现有问题不能简化为把关节 alpha 从 8 改成 5：这些属性没有发现实际读取，当前基准 CBF alpha 为 10，障碍输入还携带独立 alpha。生产 dt 为 0.01，节点默认 0.002；dt、dt_path 与发布频率分别服务积分、路径推进和 timer。不同入口或不同物理意义的数值不要求一致。

## Solution

为生产 ROS 控制入口建立明确的配置契约：生产 YAML 提供完整基值，启动显式覆盖优先，可选默认值有记录；所有值经校验、资源解析后形成一份固定的启动有效配置。每次启动持久化可追溯快照，并在日志中报告摘要与绝对路径。配置或快照失败时拒绝启动，命令流不得发布控制命令。

生产入口运行期间拒绝修改受管参数；调整后重启。离线入口保持独立默认及显式传参。遗留配置保留并标注，误用于当前生产控制参数空间时明确报错。保留当前实际生效数值、任务语义和资源解析规则。

## User Stories

1. As a 部署人员, I want a 明确的生产 YAML 权威来源, so that 我能确定控制参数基值来自哪里。
2. As a 部署人员, I want a 配置文件缺失或不可读时的启动拒绝, so that 错误路径不会被静默默认值掩盖。
3. As a 直接运行 ROS 节点的使用者, I want a 与 launch 相同的配置契约, so that 绕过 launch 也不能绕过校验。
4. As a 部署人员, I want a 控制必填项完整性检查, so that 代码默认值或启动覆盖不能掩盖 YAML 缺项。
5. As a 操作人员, I want a 启动显式覆盖优先的规则, so that 我能有意调整本次运行参数。
6. As a 维护人员, I want a 覆盖前后值及来源记录, so that 我能复现配置变化。
7. As a 操作人员, I want a 非法类型、非有限值和越界值的拒绝, so that 无效配置不能进入控制链。
8. As a 维护人员, I want a 未知字段与未接入旧控制字段的明确错误, so that 拼写错误和无效设置不会被忽略。
9. As a 控制开发者, I want a 所有消费者共用的固定启动配置, so that 构造、跟踪和 timer 不会使用不同版本的参数。
10. As a 操作人员, I want a 运行中单项和批量修改受管参数的明确拒绝, so that 参数服务与实际控制行为保持一致。
11. As a 控制开发者, I want a 分别可追溯的 dt、dt_path 和发布频率, so that 三个消费路径不会被错误合并。
12. As a 离线研究人员, I want a 保留独立默认值的控制内核入口, so that 离线实验不被生产启动门禁强制改造。
13. As a 部署人员, I want a 源码与安装 share 环境均可加载的配置和资源, so that 安装后的运行具有同样的可解释性。
14. As a 部署人员, I want a 资源空值、单项覆盖和组合覆盖的明确解析结果, so that 我能确认实际加载的轨迹与运动学资源。
15. As a 任务维护人员, I want a 圆柱轴心省略时的拟合来源记录, so that 参考几何选择可以追溯。
16. As a 通信维护人员, I want a 关节身份、数量和最终话题连接的检查与记录, so that 状态流与命令流接入符合部署预期。
17. As a 维护人员, I want a 保留且标注遗留状态的旧配置资产, so that 历史追溯及潜在外部消费者不被无依据删除破坏。
18. As a 运动学资源使用者, I want a 限定当前控制入口的遗留项检查, so that 合法运动学资源不会因包含旧控制区而整体被拒绝。
19. As a 实验复现人员, I want a 每次运行唯一且完整的有效配置快照, so that 后续运行不会覆盖证据。
20. As a 实验复现人员, I want a 配置内容与软件版本标识, so that 未提交改动不会被单一 HEAD 标识掩盖。
21. As a 操作人员, I want a 快照持久化失败时无控制命令发布, so that 缺少运行证据的启动不会继续执行。
22. As a 维护人员, I want a 日志中的快照摘要与绝对路径, so that 我能迅速找到本次运行的有效配置。
23. As a 控制开发者, I want a 使用非默认哨兵值的真实入口传播验证, so that 测试能发现同名字段没有接线的问题。
24. As a 验收人员, I want a 相同有效配置下的控制回归证据, so that 配置管理调整没有暗中改变控制算法和数值。
25. As a 验收人员, I want a 区分通过、跳过和缺少依赖的测试报告, so that 静态核验不会被误认为运行验收。
26. As a 真机执行端维护人员, I want a 与原执行链路票明确分工的配置规则, so that 本票不会重复接线或顺带启用真实后端。

## Implementation Decisions

1. 复用 rclpy 参数机制、PyYAML 和现有控制内核 facade；遵守已接受的上游复用 ADR。新增能力限于轻量参数清单、校验、来源记录和持久化，不新增配置框架、算法、依赖或 fork。
2. 修改生产启动适配、ROS 控制器参数装配与消费方式、生产配置说明及快照诊断。控制器只经 facade 访问控制内核，保留既有模块边界。
3. 生产控制 YAML 本身必须存在且可读。先检查当前控制器参数空间中的字段、必填项、类型及合法性，再应用并校验显式覆盖；不得由代码默认或覆盖补救 YAML 必填缺项。未知字段及未接入控制字段明确拒绝；其他模块合法字段不纳入此检查。
4. 最终优先级为启动显式覆盖高于生产 YAML；仅可选项允许已记录的默认值。记录实际覆盖链和覆盖前后值，直接 ROS 启动同样执行该契约。实现必须保留 YAML 与覆盖的来源边界，不能仅凭已合并的 ROS 参数反推来源。
5. 受管参数清单如下。合法域沿用当前真实消费方规则；补齐数学合法性与严格类型、有限性检查，不引入未经决议的新安全阈值，不用隐式浮点或字符串转换接受错误类型。

| 分组 | 字段 | 必填与消费要求 |
| --- | --- | --- |
| 周期 | dt、dt_path、publish_frequency_hz | 生产必填，分别进入积分、路径推进、timer；保留 0.01、0.01、100 基线。 |
| 跟踪与求解 | kp_pos、kp_orient、kp_joint、damping、w_pos、w_orient、w_joint、temporal_lambda、enable_x64、solver_tol | 生产必填，经控制循环和跟踪接口进入 facade/控制内核。 |
| 任务与进给 | task_mode、use_nullspace_policy、reference_feedrate_scale、nullspace_speed_limit、max_tool_axis_speed_rad_s、reference_lead_m | 生产必填，保留当前任务与冗余策略语义。 |
| 参考几何 | orientation_mode、cylinder_axis_direction | 生产必填，进入轨迹构造。 |
| 可选参考几何 | cylinder_center | 可省略，沿用轨迹圆柱拟合；记录来源及可得解析结果。 |
| 启动与感知开关 | wait_for_start、enable_perception_obstacles | 生产必填；补齐既有感知开关基值 false，保留 launch 显式覆盖含义。 |
| 关节与通信 | joint_names、joint_state_topic、publish_joint_state_topic、perception_tracks_topic | 生产明确列出；补齐既有感知话题默认值，不重命名话题；校验九轴关节身份、数量与唯一性。 |
| 资源路径 | trajectory_mat、portable_oscbf_root、portable_config_yaml | 允许既有空值/share 默认解析；记录原值、最终路径与来源，资源缺失或不可读拒绝启动。 |
| 诊断 | telemetry_period_s、perf_report_path、latency_budget_ms | 可选，记录默认；不把诊断预算提升为新运行周期或安全门槛。 |

6. 保留既有资源路径语义：仅覆盖控制内核 root 而 config 为空时，config 仍取安装 share 默认，不自动从覆盖后的 root 派生。生产控制 YAML 的强制加载与上述资源路径回退是两项独立规则。
7. 路径解析等启动内部赋值结束后锁定受管范围，构造参数、每步跟踪增益和 timer 使用同一份有效配置。运行期间单项及批量修改受管参数均返回明确失败，参数服务值与消费者值均不改变；启动覆盖仍可正常使用。
8. 在启动命令发布/timer 前持久化快照，使用避免半写文件的写入方式，并避免跨运行覆盖。任一持久化失败均报告原因并中止启动，不得发布控制命令。具体序列化格式及内部函数名称属于实施细节。
9. 快照包含运行标识、最终值、每项来源、显式覆盖链、资源原值与解析路径、配置内容标识、软件版本标识、输出路径。版本标识不能只写 HEAD，需反映 dirty 状态及相关源码内容摘要；日志输出摘要及快照绝对路径。拟合结果记录可得部分，不能伪造尚未得到的结果。
10. 保留基准 obstacle_h_baseline_alpha 的当前来源和值 10，说明障碍第十槽 alpha 来自运行时观测，不把未来观测写成启动固定值。保留基准 alpha 还原 h 的假设；不接通逐类 alpha。EMA alpha 是平滑系数，不能作为 CBF 增益统一处理。
11. 保留旧 torque 配置和未消费的控制字段，标注遗留状态与实际消费情况。运动学资源中的 kinematics 仍合法，不能仅因同一资源含旧 controller 区域而整体拒绝。保持安装资产，纠正过时路径、默认一致声明和 launch 注释。
12. 真机执行端模式、后端及反馈接线由原 issue #13 负责；本票提供配置契约并核对其交接和验收证据。当前问题是消费端断线，不能机械追加一层 launch 参数注入。
13. 启动拒绝与运行中修改拒绝是已接受的管理行为变化；数值与任务行为以相同有效配置为回归基线，不能将整体实现称为完全行为不变。

## Testing Decisions

主要测试边界沿用已确认交接：真实生产 ROS 控制器启动入口，贯穿生产 YAML、显式覆盖、资源解析、实际消费者和快照/命令流。优先扩展既有控制器 smoke 测试的节点构造及单步接口；现有 fixture 只使用手写 overrides，需增加真实 YAML 加载覆盖。消费者边界可观测 facade 构造、path_tracking_step 和 timer 实参，不新增多层内部测试接口；至少保留真实控制内核的必要数值回归。

好测试验证外部可观察行为和数据传播，不断言两个硬编码数值相等，不依赖内部对象布局。只比较最终控制输出不足以证明参数传播：约束不激活时输出可能相同，普通关节项在 q_des=q 时也可能为零。

| 验收项 | 必须观察的结果 |
| --- | --- |
| 生产入口 | 源码与安装 share 的真实生产 YAML 可加载；直接运行节点也执行契约。 |
| 失败门禁 | 缺失/不可读配置、必填缺项、错误类型、NaN/Inf、越界值、未知或遗留控制字段拒绝启动，无控制命令发布。合法覆盖不能掩盖原 YAML 缺项或非法值。 |
| 参数传播 | 合法非默认哨兵值到达 facade 构造、跟踪调用和 timer；快照最终值、来源及覆盖前值与真实消费者一致。 |
| 独立周期 | 分别改变 dt、dt_path、发布频率，验证各自消费路径，保留生产与离线入口差异。 |
| 资源解析 | 覆盖默认空值、单独覆盖和组合覆盖；安装资源实际可读，root 单独覆盖不改变空 config 的既有回退。 |
| 配置锁定 | 运行中单项和批量修改受管参数明确失败，参数服务、有效配置及消费者均不改变；启动覆盖成功。 |
| 快照 | 内容完整、值与来源一致、运行间不覆盖；模拟目录不可写或持久化失败，观察启动拒绝和无命令发布，不能只检查异常文本。 |
| 兼容边界 | 离线独立默认仍可用；合法运动学资源不因旧控制区被拒绝，遗留安装资产保留。 |
| 控制回归 | 相同有效参数下比较必要的任务误差、路径进给、约束残差及 QP 健康；受影响时延发生变化时补验。保留原始 QP 上界还原 h 的既有保护。 |

先例还包括控制内核现有 CBF h 复用、平滑动态障碍约束测试。动态障碍契约测试目前整模块跳过，不能列为通过证据。若实际实现触及障碍 alpha 传播，追加真实 ROS 障碍回调至最终约束行的验证：固定几何与状态，仅改变 alpha，非聚合行满足上界变化为 alpha 变化乘 h，聚合行遵循 softmin 加权 alpha 与聚合 h；非障碍行不变，全禁用无修正。未触及该链时不顺带重构。

测试报告必须区分通过、失败、跳过和缺失依赖，静态清单不替代 ROS 传播验证。硬件验收引用 #13 的隔离模式、后端和反馈证据，不由本票宣称真机准入。上述均为待执行验收，本次规格生成未运行产品测试。

## Out of Scope

- 选定新的 CBF 5/8/10 数值、启用逐类 alpha、统一各入口增益或调整控制周期。
- 新控制算法、QP 策略、任务优先级、反馈限幅及内部 damping 调优；对应可行性、控制预算与裕度策略仍归原票。
- 真机执行端 ROS 消费接线、SocketCAN 后端、反馈健康与 sim/shadow/live 模式实施；不进行真机运动。
- 删除尚未排除外部消费者的旧资产，修改其他模块合法配置或独立离线入口的默认契约。
- 新建同义 backlog、关闭原票、提交或部署产品代码；本次请求仅生成并发布规格。
