# DCOL 碰撞核心与双传感器点云规格说明书

**状态**：方案已由用户确认；实施暂缓。本次交付规格文档，代码修改等待用户后续指令。

**发布**：[GitHub 规格说明书](https://github.com/Shiningliu1011/nineaxis_safecontrol/issues/196)。

**来源与范围**：本会话 Q1–Q12 的已确认决定；适用于 ninezzhou 九轴机器人、当前工具与固定环境、双传感器观测、共享 CollisionSafety 和 OSCBF。关联[九轴曲面作业完整项目](https://github.com/Shiningliu1011/nineaxis_safecontrol/issues/147)。

## Problem Statement

项目需要一个贯通环境感知、规划检查、轨迹验证和 OSCBF 约束的碰撞核心。操作者希望直接相邻的连杆不参与自碰撞查询，其余要求检查的机器人部件获得完整检查；环境几何由 Livox MID-360S 与 Orbbec Gemini 335L 共同观测，并与已知工件、工作台等固定实体共同参与避障。

碰撞核心需要使用凸体缩放方法表达分离、接触与相交状态，提供控制所需的关节梯度和动态时间项，同时明确毫米间距、几何覆盖、观测有效范围、计算期限及失败行为。完整路径和停止过程也需要具有相同几何、场景和时间依据。

项目已有两组静态双传感器点云，以及场景准备、逐点机器人过滤、占据证据、动态运动范围和共享场景发布能力。当前数据适合验证静态几何处理；在线动态避障仍需要同步采集、机器人基座标定及受控障碍装置的实际证据。

## Solution

采用 DCOL 的最小共同线性缩放量 `proximity_scale = α`，对完整包围对象的凸体进行要求间距和误差外扩，统一使用 `h = α − 1` 构造自碰撞与环境碰撞约束。OSCBF 保留 JAX 控制框架，碰撞计算允许使用经验证的 CPU/C++ 等后端，并通过共同接口交付缩放量、导数和求解状态。

环境处理采用 PCL 与 OctoMap，参考 MoveIt2 Humble 的机器人自身点过滤及点云更新器。双传感器分别保存采集时间和射线起点，维护 `occupied/free/unknown`，将占据单元的完整体积表示为凸盒。场景同时保存观测来源、误差、有效覆盖与动态运动范围，供共同碰撞模块查询和证明。

动态实验采用铝型材框架与丝杠滑台，障碍物通过刚性支架连接滑台。双传感器估计位置和速度；丝杠设定值与实际反馈独立用于实验核验。文件回放、九轴仿真及双传感器在线接入共同构成验收范围。

### 已确认要求

| 编号 | 要求 | 验收结果必须体现的行为 |
|---|---|---|
| R01 | 相邻连杆排除 | 直接相邻关系由机器人拓扑生成；其余要求检查的对象对及其有效 primitive 组合完整参与。 |
| R02 | 机器人凸体表示 | 可以减少凸体面数或使用多个凸体；提供原始几何覆盖证明、几何误差和完整路径验证。 |

| R04 | 双传感器点云 | PCL＋OctoMap＋MoveIt2 Humble 参考实现；保留完整占据体积、来源、时间与三类空间状态。 |
| R05 | 有效覆盖 | 动作及停止所需空间必须处于有效覆盖内；一路失效后，剩余来源能够证明完整覆盖时方可继续。 |
| R06 | 受控动态实验 | 障碍物刚性连接丝杠滑台；感知估计进入避障，装置反馈用于独立核验。 |

| R08 | 连续运动检查 | 覆盖当前状态、预测状态、完整执行区间及停止过程，检查整个区间内的机器人和环境运动范围。 |

## Implementation Decisions

### I01：共同边界、坐标与时间

- `CollisionSafety` 是规划、轨迹执行与 OSCBF 共用的碰撞计算模块；复用现有场景服务、共享运动学、动态运动范围、Runtime 和参数身份机制。
- 继续使用固定的 `base_link` 环境坐标系和 `J1`–`J9` 关节顺序。J1 的移动属于机器人关节运动。两传感器安装在机器人外部固定共用支架上。
- 项目输入与报告使用 mm/°，ROS、URDF 和计算接口使用 m/rad；转换边界明确。碰撞几何、缩放量、导数和证明采用 `float64`。
- 采集、状态、预测与执行时间使用具有 `clock_id/run_epoch` 的共同物理时间及 `int64` 纳秒表示；计算耗时使用计算设备单调时钟。时间映射误差进入相应运动范围。

### I02：机器人几何与自碰撞范围

- 基座、全部连杆、滑台和当前工具具有明确的几何归属。直接相邻关系由实际机器人连接拓扑产生并记录排除原因，绑定模型、几何与策略身份。
- 所有非相邻对象对默认参加自碰撞检查；直接相邻关系是本规格确认的拓扑排除项。其余允许接触项沿用项目已有的显式登记与验证要求。
- 同一连杆可采用一个或多个凸体，每个有效 primitive 组合保持独立身份、缩放量、导数和约束行。当前十个本体 link 的串联拓扑有九组直接相邻关系，对应 36 组非相邻 link pair；工具与附件按实际归属继续生成对象对。
- 凸体允许减少面数或采用多个部分。几何制品必须完整包含原始 collision mesh 所代表的实体；组合表示必须证明实体被凸体并集覆盖。证明方法须与几何类型匹配，报告最大外扩误差、对空间占用的影响及全部输入身份。
- 完整覆盖与路径可通过性分别验收。工作台、工件形状、工具工作空间及整条蝴蝶路径使用真实几何核验；几何合并的误差与要求间距分别报告。

### I03：DCOL、几何外扩与 OSCBF

- 每个有界、非空、具有三维体积的凸体使用位于其内部且随其刚体运动的参考中心。两个已外扩凸体分别围绕各自参考中心按同一个非负比例缩放，取得两者首次相交的最小比例 `α`。`α>1` 表示外扩几何分离，`α=1` 表示接触，`α<1` 表示相交。
- 自碰撞和环境碰撞都使用 `h=α−1`。缩放量无量纲，CBF 响应率继续使用 `cbf_rate` 及 `s^-1` 单位。
- 对象对的要求间距通过几何外扩表达：双方分配的间距外扩量之和等于该对象对要求间距。自碰撞为 10 mm，机器人与环境为 30 mm。外扩必须完整包含对应欧氏球扩张；采用其他外包形式时报告额外几何误差。
- 体素体积、传感器测量、标定、机器人建模、时间映射和运动估计误差分别保存，按来源计入一次。要求间距外扩与误差外扩分项记录。
- `grad_h_q` 表达机器人关节运动的影响；`partial_h_partial_t` 包括障碍名义位姿变化和误差范围随时间变化的影响。查询、毫米距离诊断和区间证明在同一目标时间使用同一几何与误差范围。
- 保留按自碰撞、环境碰撞分别配置的固定 CBF 响应率。命令 QP 使用逐 primitive 的时间变化 CBF 条件，碰撞行不可通过 slack 放宽。
- 计算后端可以采用 JAX 或 CPU/C++ 库，选择依据为数值、导数、覆盖与完整周期结果。接口保留固定容量、批量查询及稳定 mask；跨后端数据转换和同步时间计入实际耗时。
- 导数有效性是后端验收条件。接触面切换、对称构型、导数不唯一及退化附近必须有相应数学依据与数值检查；缺少依据或求解残差超限时返回无效状态。采用平滑或外包表示时须说明实际求解几何、误差和覆盖关系。
- 独立毫米距离使用已包含误差范围、尚未包含要求间距外扩的两方几何，分别返回 `distance_mm`、`required_clearance_mm` 和两者之差 `remaining_margin_mm`。分离为正、接触为零，相交时说明穿透深度定义和结果有效性。距离用于核验和诊断；控制约束使用具有有效状态的 DCOL 结果。

### I04：双传感器点云与占据凸体

- 点云整理和空间索引采用 PCL，三维射线和占据结构采用 OctoMap；机器人几何过滤与 ROS 接入参考 MoveIt2 Humble。使用真实上游库，并记录实际选用版本和许可证。
- 雷达与相机分别保存原始采集时间、坐标系、传感器起点、标定身份、观测来源和有效范围。转换到共同坐标系后继续保留这些信息，分别建立射线证据。
- 自身点过滤使用原始机器人几何与对应采集时刻的关节反馈。机器人表面前的环境返回保留为占据；遮挡与无法明确分类的观测限制必要空间覆盖。扫描期间的机器人运动及时间误差必须进入过滤计算。
- 场景明确保存 `occupied/free/unknown`。一次有效命中立即建立 occupied；清除占据需要满足项目规定的连续、独立、时间有效的 free 证据。时间经过使证据失效或转为 unknown。固定实体与观测占据取并集，观测 free 不能清除已验证的固定实体。
- OctoMap 的空间结构服务于上述证据规则。逐来源时间、健康、覆盖、观测历史和运动误差由项目完整保存，地图的默认概率参数不单独授予动作资格。
- 占据叶单元的中心和尺寸生成六个面的完整凸盒，再执行误差及要求间距外扩。降采样、离群点处理和聚类均须保持全部有效占据及其体积；未成功关联为对象的占据也参与碰撞。
- 凸体合并必须包含全部成员及其有效误差、来源和运动范围，报告合并后的空间占用。合并后重新验证通道和完整路径；无法在容量内保持所需证明时返回容量错误。
- 体素尺寸、空间范围和观测时间窗由已有点云、受控实验条件及完整周期测量共同确定。最小可检尺寸、物体材质、距离、扫描分布和可见性属于对应配置的适用范围。射线间的观测空隙需要符合已验证的检出条件。

### I05：动态障碍与必要空间覆盖

- 实验装置采用铝型材框架、丝杠滑台与刚性连接的障碍物。障碍物尺寸、滑台轴向、行程、速度、加减速、换向、起始相位及测量方式在实验前形成版本化配置。
- 运行中的障碍位置、速度及关联状态来自双传感器观测估计。装置设定值和实际反馈作为独立评价数据保存，不作为该实验中碰撞控制的运动信息输入。
- occupancy 表示障碍存在事实。可信 tracking 提供名义运动与估计误差；跟踪中断保留障碍，并使用有来源的未跟踪运动上界。缺少适用运动上界时，相应动作不能取得有效证明。
- 动态范围覆盖从原始观测时刻到当前及完整预测、执行和停止区间。加减速、换向、传输延迟及估计误差计入范围；合并范围完整包含每个成员的未来运动。
- 每次请求根据完整机器人和工具、要求间距、误差及动作和停止过程生成必要空间。查询必须证明该空间包含在仍有效的覆盖范围内；未知、遮挡、歧义、网格边界和外部运动进入该范围的可能性均需检查。
- 一路传感器失效后，仅当剩余有效来源能够独立证明必要空间完整覆盖时继续。覆盖不足时执行现有停止与等待规则；恢复遵守 Runtime 的状态和重新验证条件。

### I06：共享场景、公共接口与失败处理

| 公共操作 | 必须提供的行为 |
|---|---|
| `prepare_scene(scene, identities)` | 核验几何、标定、来源、布局、容量、时间与覆盖，生成不可变 `PreparedScene`。 |
| `query(query_batch, prepared_scene, query_mode)` | 按每个状态的目标时间返回状态有效性、独立 DCOL 行或毫米距离；完整保存结果身份和期限。 |
| `certify(segment_batch, prepared_scene)` | 结合实际连续运动及环境未来范围，对整个区间给出证明结果、下界及失败区间。 |

- 以上公共验收入口已在 Q12 的完整方案中确认。ROS 接入和各调用方共用这些操作及其结果含义。
- OSCBF 结果包含 `proximity_scale`、`barrier`、`grad_h_q`、`partial_h_partial_t`、`valid_mask`、primitive pair identity、solver residual、iteration 与 health；结果带 `geometry_hash`、`kernel_version`、策略身份、场景 epoch/revision、目标时间和 deadline 状态。
- `collision_scene_server` 继续作为场景唯一写入者，发布完整不可变场景；各消费者验证布局、身份、checksum、版本和时效后使用本地副本。感知准备与控制查询分别调度。
- 候选筛选和活动集合必须证明省略对象对在所需时间区间内具有安全下界。需要的对象或约束超过容量时返回相应错误，不能获得有效 mask。
- 非法 shape、单位、配置和程序调用在接口处立即抛出异常。运行中的无效场景、覆盖不足、容量不足、求解异常、证明失败和超期返回现有明确状态；只有 `OK` 且 mask 有效的结果可以参与准入。
- 故障处理继续使用 Runtime 的停止、等待、锁存和恢复规则。零速度请求、命令保持与实际停止反馈分别记录。新核心取得命令权限前需要完成对应运行模式的证据检查。

### I07：完整运动证明与周期

- `certify` 使用实际执行的九轴连续运动及停止运动描述，绑定模型、场景、策略和命令身份。证明范围包括机器人与工具在整个区间内的运动，以及障碍物在同一区间的可达范围。
- 可采用有依据的区间下界与自适应二分。端点及离散样本用于辅助核验；有效证明覆盖全部连续区间。计算预算不足、必要空间不足或下界无法成立时返回未通过。
- 场景、几何、标定、参数或运动身份改变后，相关未来证明重新核验。规划、执行前视、停止及 OSCBF 使用相同几何和时间含义。
- 控制周期 `T` 按目标计算设备完整测量与物理限制确定。完整计时从输入读取、对时和队列检查开始，包含任务与限制、碰撞查询、QP、Ruckig、参考协调、运动和停止检查、准入、命令提交及必要记录。
- 场景生产、后台计算和数据传输分别记录耗时、队列、年龄与实际生效延迟。异步执行仍须满足数据时效和物理期限。
- 每个候选周期至少取得 10,000 个完整周期样本，要求 `p99.9_complete ≤ 0.8 × T`；最大完整耗时加时钟和调度误差仍须满足实际生效截止时间。周期同时满足反馈、任务误差、场景、停止和设备保护限制。
- 根据完整项目规则选择符合全部条件的最短整数仿真 tick 倍数，并在该周期重新验证。没有同时满足条件的周期时，相应运行配置保持不可用。

### I08：参数、证据与文档

- 体素尺寸、凸体数量、误差范围、观测期限、跟踪运动上界、CBF 响应率、查询容量、solver 容差和计算预算通过版本化参数制品保存，记录数值、单位、来源、适用工况和验证结果。
- 模型、原始 mesh、凸体、相邻关系、传感器来源、标定、数据、后端、参数和场景布局具有可复现身份。影响几何或准入含义的变化需要重新验证相关证据。
- 实现时同步维护领域词汇、相关 ADR、运行入口、配置和验收说明，使其统一表达本规格确定的相邻关系、凸体、双传感器、几何外扩和周期含义。

## Testing Decisions

### 公共验收入口与原则

主要验收入口为 `CollisionSafety.prepare_scene/query/certify`，并通过真实场景服务、控制消费者和 MuJoCo 验证完整行为。测试检查公开结果、身份、状态、数值、被接受的运动及实际输出，不依赖内部函数安排。

数值参考采用解析几何、独立高精度求解与官方 DCOL 参考。既有程序的输出可以辅助定位差异；正确性由独立依据、覆盖证明及连续证明确定。测试使用真实库、真实消息与进程边界，仿真采用明确的机器人和传感器模型。

| T11 | R07 | 真实服务和消费者、共享内存、重启、revision/身份变化、checksum 损坏 | 唯一写入和不可变发布成立，读者拒绝不完整或失效输入。 |

### 复用的测试基础

现有测试已覆盖公共 CollisionSafety 结果与状态、`PreparedScene` 身份及时间、几何制品、官方 ellipsoid DCOL 参考、逐点自身过滤、占据证据、动态未来范围和真实共享场景进程。沿用这些公共入口，扩展到本规格的凸体、双传感器及完整运动要求。

### 参数确定与完成条件

- 参数开发数据与最终验收数据分开；在正式验收前固定输入身份、容差、工况、随机种子、容量和通过条件。
- 几何误差、导数误差、最小可检尺寸、动态速度和加速度范围、观测期限及完整周期均提供测量或数学依据。现场数值尚未具备时记录取得方式和适用限制。
- 报告至少包含 p50/p95/p99/p99.9/最大耗时、超期及拒绝数量、端到端年龄与生效延迟，并保存全部失败和未完成记录。
- 每项证据绑定代码 revision、依赖版本、模型、几何、参数、标定、数据与计算设备身份；能够从公开运行入口复现。
- 规格完成表示需求已经明确。软件完成需要相应实现与测试证据；完整验收还需要文件回放、九轴仿真和实际双传感器在线条件对应的证据。各项状态独立记录。
