# 跟踪执行状态与过渡执行结果优化规格说明书

**状态**：本规格补充执行结果、状态读取和报告生命周期要求；实施与验收共用[完整项目地图 #147](https://github.com/Shiningliu1011/nineaxis_safecontrol/issues/147)中的任务。

**依据**：[总体规格 #145](https://github.com/Shiningliu1011/nineaxis_safecontrol/issues/145)、[DCOL 与双传感器规格 #196](https://github.com/Shiningliu1011/nineaxis_safecontrol/issues/196)、[模块边界与复用规格 #197](https://github.com/Shiningliu1011/nineaxis_safecontrol/issues/197)。当前用户确认及两份专项规格在各自范围内优先；进度、Runtime、运动和评价遵循各自公共模块的要求。

## Problem Statement

跟踪与过渡调用需要明确每项状态的负责对象，能够区分候选、获准运动、实际采用、执行进度、阶段结果和整段完成。ROS callback、自动重试、评价和报告应当消费稳定的公开结果，使内部计算及存储调整能够集中在相应模块。

## Solution

通过公共模型、参考、限制、碰撞、状态、运动、执行记录和评价完成跟踪与过渡。Runtime 管理阶段，M05 提供有效反馈快照，M06 的 `ProgressLedger` 唯一结算执行参考，M10/M11 核验和采用运动，M12 读取实际记录进行评价。ROS adapter 负责消息、调度及结果展示。

过渡执行提供不可变的结构化结果，分别记录规划、运动采用与完成、交接请求及交接响应。各类结果码和对应成功值由一个定义产生，进程内调用直接读取结构化事实。报告保存状态与运行结果分别管理。

## User Stories

1. 作为维护者，我希望每项阶段、进度、运动与报告状态具有唯一负责对象，以便通过公开接口修改和验证行为。
2. 作为运行人员，我希望实际执行记录决定参考进度，以便正确处理拒绝、部分执行、停止余运动和恢复。
3. 作为运行人员，我希望完成判定具有实际覆盖、任务误差及停止保持证据，以便判断作业是否满足要求。
4. 作为评价人员，我希望实际反馈、候选与预测记录分别声明来源，以便独立重算整段运行结果。
5. 作为过渡调用方，我希望直接读取执行和交接事实，以便 Runtime 按已确认规则进入后续阶段。
6. 作为维护者，我希望 ROS 请求与自动重试共用公开入口和并发准入，以便请求获得一致结果。
7. 作为运行人员，我希望报告保存异步完成且结果可观察，以便文件 I/O 遵守控制周期预算。
8. 作为验收人员，我希望正式 launch 与公共数值接口提供真实结果，以便复核每项要求及其适用范围。

## Implementation Decisions

### I01：状态职责与进度

- Runtime 唯一管理开始、入场、加工、暂停、恢复、终点和退出等阶段，阶段与异常处理沿用总体规格及 #151 的已确认规则。
- M05 提供带来源、时间、有效范围和身份的反馈；M06 通过 `ProgressLedger` 按 `ExecutionReceipt` 确认的实际采用区间，对相应 `nu_exec(t)` 积分。重复记录最多结算一次，部分执行和停止余运动按有效区间结算，缺失或冲突记录保持明确状态。
- `s_plan`、`s_ref`、`s_tool` 分别记录。实际工具进度采用有序局部投影并检查自交分支，历史执行参考保持原值。控制器、跟踪适配器、显示和评价通过公共结果读取进度。
- 开始、结束及重复请求遵循 Runtime 的运行身份和幂等规则。无有效反馈时不能生成依赖该反馈的新运动，停止、等待、锁存与恢复按已确认规则执行。

### I02：运动与完成

- 控制与过渡规划提供候选；公共运动模块从有效 `q/qdot/qddot` 接续，生成完整连续运动及停止。M10 对具体运动、参考、限制、场景、时间和停止条件进行准入，M11 采用获准对象并报告实际执行事实。
- 运动变化后重新生成相应参考和证明。关节速度、加速度与 jerk 使用公共限制，Ruckig 依赖及取消条件采用 #197 I08。
- 参考到达终点作为 Runtime 的检查事件。整段完成依据有序实际覆盖、位置和工具轴误差、有效反馈及停止保持条件；安全退出按已确认阶段规则完成。命令拒绝、停滞、暂停和中断保留各自原因及已执行区间。
- 运行入口、配置与方法可用性采用 #197 I03。过渡与感知演示通过共同模块运行，具体可用能力由实际实现和验证结果声明。

### I03：结构化过渡结果

- 公开结果至少包含阶段、结果码、该阶段成功值、轨迹点数、规划用时及计时范围、诊断上下文、运动与执行记录身份、是否请求交接、交接响应和失败原因。未请求、不可用、超时、拒绝及接受分别表达。
- 结果码与成功值共用一个定义。运动阶段完成、交接被接受和整段作业完成分别记录；Runtime 根据所需阶段的全部条件决定后续动作。
- ROS 请求与自动重试共用本地执行入口和执行中状态，统一处理就绪、并发、结束与资源释放。重试遵循 Runtime 的有效反馈、准入和恢复条件。
- 对外文本只由 ROS adapter 编码。兼容接口保留其声明阶段的结果含义，适配和迁移由 #202 统一维护；进程内消费者无需解析文本或构造 Trigger 往返。
- 模块调用错误在发生位置报告；运行期失败保留实际完成阶段与原因，后续阶段按公共状态处理。

### I04：评价与报告生命周期

- M12 只读共同参考、实际反馈、`ExecutionReceipt` 和 `ProgressLedger` 结果，从原始记录独立重算路径、轴向、工具运动、关节限制、完整结束、耗时及失败指标。
- 模型候选与预测数据具有各自边界和身份。实际反馈缺失、身份失配或导数无效时，对应评价保持无效；未测量距离明确表示未测量。
- 停止过程、停止余运动和完成所需保持区间的实际证据纳入记录。终止事实满足相应条件后固定，一次运行的终止报告最多提交一次，重复结束保持幂等。
- 报告写入采用独立的 `idle/writing/saved/failed` 状态，写入失败不改写已确认的运行结果。控制 callback 不同步等待报告序列化或文件写入；记录耗时和数据丢失可见。
- 关闭时终止新调度，按 Runtime 规则处理当前运动并完成必要记录，将未完成运行准确标为中断，等待报告资源收尾后释放节点。显式同步导出通过控制 callback 之外的公开入口进行。

### I05：实施责任

| 责任 | 实施任务 |
|---|---|
| M05 状态与 M06 进度结算 | #155 |
| 连续运动、停止、M10 准入与 M11 执行记录 | #156 |
| Runtime 阶段、过渡及交接协调 | #158 |
| M12 记录、评价与报告生命周期 | #159 |
| 共同入口、配置、ROS 适配与消费者迁移 | #202 |
| 独立作业仿真及现有功能整合验收 | #160、#204 |

本规格由上述任务共同交付。既有类和公共接口按职责复用，完整 MPC、完整逐点方法和三方法正式比较由原任务继续实现。

## Testing Decisions

主要集成入口采用正式 final launch、真实 MuJoCo、公开请求、命令、反馈、执行记录和报告；必要数值验证复用公共接口。测试使用真实库、数据与进程，观察公开行为和实际结果。

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| A01 | 首次与重复开始、并发请求、未就绪输入 | Runtime 阶段和运行身份一致，初始化与执行准入保持幂等，拒绝原因可观察。 |
| A02 | 完整、部分、重复、乱序、缺失和冲突执行记录 | M06 依据有效执行区间结算；停止余运动计入，缺少证据的区间不能推进参考。 |
| A03 | 参考终点、实际滞后、自交路径、末端误差超限 | 实际覆盖和误差检查完整，只有全部完成条件成立才能报告完成。 |
| A04 | 加减速、停止、暂停恢复、候选拒绝、超期和反馈失效 | 实际采用对象、连续运动、完整停止及状态接续满足共同准入规则。 |
| A05 | 规划失败、运动采用或执行失败、交接未请求及各类响应 | 结构化结果准确记录执行阶段、原因、成功值和交接事实，Runtime 遵循相应进入条件。 |
| A06 | ROS 请求与自动重试、公开结果编码和兼容接口 | 共用本地入口和结果定义，文本忠实表达声明阶段，调用方消费结构化结果。 |
| A07 | 实际反馈、候选记录、缺失反馈、未测量距离及身份错误 | 来源明确；实际指标可从原始反馈重算，无效数据不能产生合格结论。 |
| A08 | 报告保存、真实文件系统写入失败、重复结束及运行中关闭 | 报告最多提交一次，保存状态可观察；控制周期遵守预算，资源收尾完整。 |
| A09 | 实际安装入口及公开状态、时延和报告工具 | 消费共同配置、状态与身份，工具无需访问内部字段；运行说明与实际行为一致。 |

每项验收保存命令、输入、源码、模型、配置、场景、运行身份及原始结果。时延范围采用完整项目要求，报告各分项、完整周期、数据年龄和生效时间。软件、仿真及现场证据分别记录；未运行或未通过的检查保持未完成。

与模块规格的对应为 `#197:T01/T02` 公共边界、`#197:T03/T04` 入口及配置、`#197:T07` 运动和异常、`#197:T08` 反馈进度及评价、`#197:T09` 安装入口与真实仿真回归。

## Out of Scope

- 本次规格维护中的控制算法实现、软件运行方式切换、设备动作及硬件准入变更。
- 在本规格内新增完整 MPC、完整逐点算法或正式三方法实验。
- 创建另一套阶段、执行进度、限制、碰撞或评价规则。

## Further Notes

规格确认与软件行为通过分别管理。已有验证记录保留其输入、代码与测量边界，当前要求由相应任务取得证据。实现前读取目标代码和消费者，保护现有修改，同步维护实际运行说明和公共接口文档。
