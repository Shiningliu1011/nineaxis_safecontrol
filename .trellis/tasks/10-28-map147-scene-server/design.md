# 设计与修改边界

现有 self-filter、占据、固定模型、dynamic support 与 `CollisionSafety.prepare_scene` 均已具备各自公开接口；跨进程唯一发布和读取入口尚缺。新增共享场景传输模块及独立 ROS 场景服务，直接组合现有生产能力，消费者继续使用 `PreparedScene`。

共享布局与原子发布属于传输模块；必须使用可靠的进程间原子操作或成熟库。header 保存布局及完整身份，slot 保存可重建的所有场景字段、时间模型与固定环境来源。读取者校验复制前后的发布身份，发现切换、跳跃、损坏、过期或 epoch 改变均撤销旧场景使用资格。控制查询只使用已经准备的本地副本，场景刷新位于独立路径。

ROS node 与场景处理纯逻辑分开；node 负责消息适配、资源和生命周期，场景管线拥有全部处理状态。配置通过现有 artifact、geometry、外参与固定环境入口取得，缺少依赖或无效输入立即报告。

预计修改范围：新共享传输模块、场景服务及配置、公共 ROS topic、setup/package 安装入口、对应测试及模块说明；仅在组合现有公开接口确有需要时修改消费者接口。硬件、正式控制切换和现场测量保持各自任务范围。

公开测试边界已经由任务验收明确：实际 server 进程、实际共享 slot、读取者公开刷新接口、真实 JAX PreparedScene，以及 LiDAR→过滤→占据→support→prepare→发布完整管线。实现子 agent 按逐项 TDD 保留失败和通过命令。
