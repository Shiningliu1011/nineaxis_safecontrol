# 模块实现与已有决定核查

## 目标

核查各模块的实际入口、默认配置、并行实现与已确认决定，明确修改范围并形成规格说明书；当前范围为审查、决策和文档。

整合具有共同职责的实现，复用已经具备的能力；能够用同一种方法满足要求时采用一个正式实现，使调用关系、配置来源和状态管理清楚。

各模块分别维护职责、代码和测试，通过公共接口协作。本轮修改范围为现有功能的模块边界、复用、重复实现清理及必要的替换接入。完整 MPC 等新增能力继续按既有任务实施。

## 要求

- 覆盖机器人模型与运动学、传感器、环境场景、碰撞、作业参考、规划、控制、执行流程、安全检查、执行器、显示和评价。
- 每项实现选择均追踪实际入口、有效配置和调用位置，明确默认运行、显式可选、独立实验、数值参考或尚未接入的用途。
- 使用用户当前要求、可恢复的历史原文及已确认规格核验选择；设计决定与当前完成程度分别记录。
- 同一模型的不同计算后端、正式比较方法和独立验算方法按其用途核查，存在多个文件本身不构成问题。
- 用户已明确机器人包络采用已有 OBB，并要求舍弃椭球包络。此次继续以该要求为依据。
- 正式闭环统一使用 `run_demo.sh`，显式选择 `pointwise_ik`、`realtime_coordination` 或 `predictive_coordination`；感知与过渡演示使用共同模块和场景配置。
- 三种正式比较方法共用模型、限值、场景、碰撞、任务参考、执行和评价。方法差异仅保留在其已经确认的算法职责内。
- 已被替换且没有独立用途的业务实现、配置、入口和专用测试纳入清理范围；仍有效的行为要求由共同接口的测试覆盖。
- 独立数值验算和单关节设备检查按明确用途保留。它们的输入、结果和运行身份可追踪。
- 独立 Python 规划 benchmark 及其专用近似实现移除；正式 AEB-RRT* 规划继续保留并复用共同模块。
- 速度、加速度和 jerk 的共同限值及 QP 接入要求沿用大地图 #138/#143；规格决定、默认代码现状和已验证行为分别记录。
- 以取消 Ruckig 为目标；现有功能没有经过验证的替代实现时保留，将其依赖集中在运动生成边界。替代方案须覆盖连续运动、完整停止、约束、执行和失败处理。
- 相同物理量、参考进度和场景状态具有明确的来源与负责对象；演示或方法不得复制其维护逻辑。
- 将能从仓库查明的事实写入证据记录，只向用户询问会改变要求或验收的未确定事项。
- 当前确认及两份新规格在各自范围内优先于旧地图的冲突描述。受影响任务的范围、验收和前置关系应当使用当前要求；已有完成证据保留其原有适用范围。
- 经用户确认的决定保存在本任务；本次规划给出复用位置、整合范围及验证要求，功能实现按审阅后的具体范围推进。
