# 正式实验管理

正式目录保存只读清单、每个配置及其 SHA-256、共同周期选择记录、
开发场景与可行性证据、代码和模型归档、环境身份。
清单包含 1,080 个固定运行编号，编号由场景、初态、进给、方法和重复组成。

执行器逐项核对固定身份，串行启动已有完整 ROS 仿真入口。
恢复执行时检查已完成记录；异常退出和未完成目录保存并进入统计，
不覆盖已有原始数据。代码、环境或配置变化时终止批量运行。

配对报告使用相同场景、初态、进给和重复编号关联两种方法。
失败率及完成率使用全部已计划组合；连续指标同时报告成对有效数量，
保留失败及缺失状态，避免从有效子集推断整个实验集的结论。
图表与独立评价复用共同反馈格式。

正式运行要求共同周期已经通过，且开发证据和参数均已经保存。
尚未满足启动条件时清单管理可以验证，正式数据不能标记为已取得。

## 紧凑存储与主机接手

数据库继续逐条提交 SQLite WAL。新记录使用 MessagePack float64 与 zlib
无损压缩，同一 stream 的前一条解码内容提供最多 32 KiB 字典，每 128 条
独立开始，限制随机读取需要解码的范围。sequence、三个时间字段和 stream
仍为 SQLite 列；格式由 user_version 明确区分。旧 JSON 记录只读兼容。
有限数值检查保持有效，压缩字典仅在事务成功后推进。

存储行为属于 `static_experiment_recording.py`；评价和 S4 见证通过统一读取
接口使用两种格式。迁移写入新目录，逐条核查内容身份并保存来源文件 SHA-256、
转换后数据库身份和格式。源 manifest、result、path 及原始报告保持可追溯。
新报告绑定转换记录；记录身份变化时拒绝使用报告。

逐反馈派生数组默认按需生成，汇总评价照常完整重算。绘图在独立中间目录生成
数组，并核查重算指标与已有报告一致；不改变原始运行的报告身份。迁移和
数据格式属于需要独立规范、需求审查的范围，审查基准为 `6afe1d34`。
