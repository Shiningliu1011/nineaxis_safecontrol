# 设计

## 修改边界

模型定义由 URDF 提供。修改 J1 origin 与行程，更新已有生成资源和来源身份，检查 JAX、MuJoCo、MoveIt、独立规划器及运行配置消费者。保留历史实验资产与原坐标来源，对旧模型身份保持明确拒绝。

执行保护位于 single_joint_execution.py 的反馈验证、速度窗口、ArrivalWindow 与异常保持路径。用真实回放建立可重复的失败信号，核对请求、接收与设备采样时间的区别。保护数值沿用已确认范围；改变判据必须记录计算依据。位置可信性与运动速度限制分别用于判断保持请求是否允许，保持后的观察继续验证停车。

本次只进行本地模型、纯逻辑、回放、安装与文档验证。真实动作、设备写入、清错、解除锁定及 ROS live 不在授权范围内。缺少完整记录或厂家对应版本证据的结论保持未验证。

## 验证边界

- 模型：使用基点 URDF、真实模型加载器与现有几何路径比较相同物理位置；检查共同模型与资源安装。
- 设备：只使用本地原始帧和纯逻辑对象，无硬件 transport、mock 或厂家 SDK import。
- 停车：区分保持请求、命令返回、持续反馈观察、物理停止和人工确认。
- 高风险修改完成后按 Standards 与 Spec 分别审查。

## 标定姿态表

新增 joint_table.py 管理 CSV 姿态输入、共同模型身份和逐组状态；joint_table_cli.py 提供本地检查命令。CSV 使用 pose_id、J1_mm、J2_deg 至 J9_deg。完整目标直接使用关节坐标，不经过 IK。复用 robot_units 的单位换算、NineaxisModel 的位置范围与 FK。

相机与激光跟踪仪会话独立选择 camera 或 laser_tracker，记录各自采集文件与 SHA-256。当前状态流程只接受明确标识的 MuJoCo 仿真反馈；所有关节持续满足位置和速度条件后才允许关联采集文件，关联完成后才允许选取下一行。命令返回与人工声明不能推进到位状态。joint_table CLI 的 execute 请求明确拒绝，不创建 transport。

标定采用完整关节绝对目标直接提交，复用 J1ScrewControl 与 DrEmpowerJointControl 的设备坐标、速度和加速度换算。驱动器使用既有梯形位置模式完成运动，各轴可以重叠运动，全部持续到位后采集，记录完成后才允许下一组。目标和反馈必须保留共同模型、设备节点、零位及时间身份。

本次不增加相机或跟踪仪外参求解，不开放多轴真实 I/O，不提高真实运动速度、加速度或保护参数。仿真配置不提供真实执行授权。

后续研究方向为直接在 OSCBF 求解中加入速度、加速度和加加速度约束，核查离散化、当前运动状态及连续时间的限制。研究继续使用共同模型、单位及限制来源。本次不更改 OSCBF 优化问题。

## 物理轨迹与起点

轨迹到 base_link 的共同变换使用明确的 trajectory_span_m 和 ee_center；保持既有351 mm物理尺寸及工件位置，模型坐标调整不改变实验曲线。修改发生在 ik_data_loader.reference_trajectory_transform 与两个实际调用点，配置及连续包来源同步更新。

S0/S1 初始 J1 按85 mm关系转换。原始跟踪 START 位于共同物理行程外，使用 SciPy 有界 least_squares 及 START_IK_MIN_JOINT_MARGIN 从原姿态附近求解当前路径首点，目标遵守 tool_axis_5d 的位置及工作轴定义，保存模型、路径身份与误差，并供TrackingRun、ROS smoke与过渡测试共用。原路径长度、进度、误差、静止及性能要求保持。

原 S0 终点记录保留原始字节及身份。当前模型的终点求解检查使用 static_terminal_configuration_j1_origin85mm.json 明确标识的仿真初态，保存同一 S0 进度、模型与路径身份、原记录 SHA-256、FK 与工作轴误差及共同关节余量。实际 QP 和独立 SLSQP/KKT 继续检查当前配置；仿真初态不作为历史执行或物理停止证据。
