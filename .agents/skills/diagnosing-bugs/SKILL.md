# Diagnosing Bugs

此项目采用 Matt Pocock `diagnosing-bugs` 的反馈循环。来源版本记录在 `.agents/skills/trellis-local/SKILL.md`。

1. 根据用户报告建立能够观察原症状的运行命令或测试，记录输入、环境、预期结果和实际结果。真实设备操作仍按项目授权边界处理。
2. 运行该命令，确认原症状可以重现。逐步缩小输入和调用范围，并保留仍能重现问题的条件。没有可运行的复现方式时，记录具体缺口，向用户索取必要的环境或记录。
3. 在复现证据的基础上列出可以验证的原因，逐项用调试器、定向日志或测量数据检查。性能问题记录修改前的数值。
4. 用户授权修复时，在合适的公开接口上添加有意义的回归测试，修复原因，再运行回归测试和原复现命令。遵守项目禁止 mock 的规则。
5. 用户授权任务文件修改时，移除临时诊断代码，并在当前任务的 `research/diagnosis.md` 记录复现命令、症状、原因、修改和验证结果。进入 `trellis-check` 前完成这份记录。

用户仅要求诊断时，报告经过运行或源码证据支持的结论，不修改代码或任务文件。Trellis 继续管理任务状态、规范和最终检查。
